# Project Satellite · 1단계

> 최신 화면·장치 구조와 연결 사용법은 [Dock 재설계](MOONS_DOCK.md)를 따릅니다. 아래는 최초 1단계 구현의 기록입니다.

## 제품 범위

MOONS는 사용자의 생각과 프로젝트를 연결하는 공간이다. 새 덤프가 특정 프로젝트에 태그되거나, 연결한 프로젝트에 적용할 수 있다고 판단되면 MOONS가 검토안을 준비한다. 사용자는 알림에서 검토안을 열어 MOONS와 논의하고 명시적으로 안건을 확정한다. 확정본은 Claude Code/Codex에 전달할 Markdown 지시서가 된다. 실행 결과를 지시서 버전에 연결해 기록한다.

이번 단계의 알림은 MOONS 내부 알림이다. 브라우저를 닫아도 API 서버가 실행 중이면 검토 작업은 진행된다. OS 푸시·이메일, 코딩 에이전트 자동 실행, 자동 병합·배포는 후속 단계다.

## 사용 흐름

1. Satellite → 연결 → 프로젝트를 켜고 프로젝트 화면을 연다.
2. 이름·목표를 입력한다. 기존 일정 프로젝트를 선택하면 같은 프로젝트 ID에 연결한다. GitHub 저장소, 서비스 주소, 맥락 노트와 파일 경로를 지정할 수 있다.
3. 공개 저장소는 토큰 없이, 비공개 저장소는 해당 저장소 읽기 권한만 가진 GitHub 토큰을 저장한 뒤 **저장소 확인**을 누른다. 기본 브랜치의 SHA, 최신 커밋, checks, 파일 목록 및 지정 파일 내용을 기록한다. 저장소 상태는 마지막 확인 시점의 스냅샷이다.
4. 다른 AI와의 대화는 **대화·맥락 추가**에서 원문과 출처를 저장한다. 현재는 텍스트 가져오기이며 브라우저 확장/MCP의 자동 대화 수집은 후속 단계다.
5. 새 덤프에 프로젝트를 태그한다. 태그가 없으면 관찰 중인 프로젝트들에서 최대 3개를 자동 매칭한다. 기존 원문 화면에서 프로젝트 태그를 추가해도 검토를 시작한다. 단순 열람·다른 메타데이터 수정은 재실행하지 않는다.
6. 알림/검토함 → 제안 이유·변경 범위·보존할 동작·완료 조건·검증 방법을 읽고 MOONS와 논의한다. 직접 수정할 수도 있다. 미결정 사항이 있으면 확정할 수 없다.
7. **안건 확정** → 지시서를 복사/다운로드해 코딩 에이전트에게 전달한다. 대화에서 동의하는 것만으로 확정되지 않는다.
8. 전달 완료를 표시하고 PR 주소·실제 테스트 결과를 기록한다. 결과는 보고값이며 독립 검증되었다고 표시하지 않는다. 재논의 시 기존 확정본은 보존하고 다음 버전을 만든다.

## 데이터와 작업 처리

- `connected_projects`: 소유 공간, 목표, 원문 맥락, GitHub 스냅샷, 설정 버전. 암호화한 GitHub 키와 해시한 수신 토큰은 응답에서 제외한다.
- `project_jobs`: 덤프 저장 트랜잭션 안에서 큐 생성. 공간/원문/정렬된 태그 조합으로 중복 방지. DB lease, heartbeat, 재시도 3회, 실패 후 수동 재시도.
- `project_proposals`: 원문 및 검토 당시 맥락, AI 초안, 논의, 명시적 승인으로 만든 불변 지시서, 버전별 작업 결과. 수정은 revision 비교로 충돌 감지한다.
- `project_events`: 앱이 보고한 사용량·오류·배포·비용. 프로젝트별 이벤트 ID로 재전송 중복 방지.
- 기존 공간 소유권과 AI 키/일별 한도를 사용한다. 익명 공간을 계정에 합칠 때 프로젝트·검토안·작업·측정값도 이동한다. 다른 사용자의 공간은 검색/조회/변경할 수 없다.
- 프로젝트 관찰 또는 Satellite을 끄거나 태그를 바꾸면 진행 중인 검토 결과도 등록 전 다시 검사한다. 이미 시작한 모델 호출의 비용은 취소되지 않는다.
- 입력 문서와 대화는 참고 자료다. 모델이 알려지지 않은 프로젝트 ID나 확인되지 않은 코드 경로를 반환하면 제거한다. 코드 내용을 읽지 않았다면 코드 검증을 완료했다고 보장하지 않는다.

## 사용량·비용 연결

프로젝트 화면에서 수신 토큰을 발급하고 앱 **서버의 비밀 설정**에 저장한다. 토큰은 한 번만 표시하며 교체/폐기할 수 있다. 이 토큰은 해당 프로젝트에 이벤트를 추가하는 권한만 갖는다.

`POST /api/project-events`, `Authorization: Bearer <token>`, `Content-Type: application/json`:

```json
{"id":"request-123","kind":"cost","name":"LLM request","value":0.0012,"unit":"USD","at":"2026-10-26T00:00:00Z","source":"my-app/openai","basis":"estimated","aggregation":"sum"}
```

- `kind`: `usage`, `error`, `deployment`, `cost`.
- `aggregation: sum`: 요청별 증분을 합산한다. 기본값이다.
- `aggregation: latest`: 누적 청구액·현재 사용자 수 등 스냅샷의 최신 값만 표시한다.
- `basis`: `estimated`(추정) 또는 `reported`(보고값). 공급자 청구서와 검증되었다는 뜻이 아니다.
- 비용 단위는 대문자 통화 코드. 통화/출처/산정 기준이 다른 값은 합치지 않는다.
- 최근 30일 전체를 서버에서 집계해 이벤트 개수 제한으로 비용이 누락되지 않도록 한다. MOONS 자체 AI 비용은 기존 호출 로그와 모델 단가표를 이용한 별도 추정치다. 가격 미상 호출은 따로 표시한다.
- 서버용 예제: `examples/project-events.mjs`. 실제 앱에서 이벤트를 전송하기 전에는 빈 화면이 정상이다. 공급자별 관리 API 청구 내역 자동 수집은 아직 없다.

## 운영

기존 API 서버 시작 시 테이블을 `create if not exists`로 초기화하고 작업자를 시작한다. 상시 실행되는 서버와 지속 DB가 필요하다. `MOONS_PROJECT_WORKER=off`로 자동 처리를 끌 수 있다. GitHub 키 저장에는 `MOONS_ENCRYPTION_KEY`(기존 `SESSION_SECRET` fallback)가 필요하다. AI는 기존 운영자 설정/사용자 키와 한도를 따른다. 프로젝트 AI 작업은 설정의 “프로젝트 업데이트” 단계에서 모델을 선택한다.

지원 HTTP 경로는 `artifacts/api-server/src/moons/projects-router.ts`에 있다. 프로젝트 관리와 대화 API는 기존 세션 인증·소유 공간 검사를 사용한다. 임의 외부 플러그인에 읽기/승인용 장기 토큰을 발급하지 않는다. 후속 MCP 연결에는 별도의 범위 지정 권한과 명시적 사용자 연결 흐름이 필요하다.

## 후속 단계

실사용 모델 품질 평가 → 공급자별 청구/배포/분석 커넥터 → OS 푸시 → 대화 수집 플러그인 → 승인된 지시서만 실행하는 에이전트 어댑터 순으로 확장한다. 자동 실행 단계에는 실행 환경, 권한 범위, 예산, 중단, PR 검증 및 승인 기록을 추가한다.
