# Moons 웹 — 기능 정리 v0.1

> 기준: `1dyne/moons-lofi` (옵시디언 플러그인 v0.1.x) 코드 전체 검토.
> 원칙: **기능은 가져오고, 복잡함은 백엔드로 숨긴다.** UX는 새로 만든다.

---

## 1. 사용자가 겪는 흐름은 이것뿐이다

```
① 생각나는 대로 적는다
② AI가 내 생각을 그대로 시각 구조로 보여준다   (보정 없음)
③ AI는 두 가지만 알려준다: 잘못 알았을 수 있는 곳 / 더 공부할 곳
④ 공부하거나 새로 알게 된 걸 그 자리에 적어 업데이트한다
```

사용자는 이미 "내가 뭘 모르지?"를 붙잡고 고민하는 사람이다.
그래서 **이 네 단계 외의 선택·설정·기호·용어는 하나도 보여주지 않는다.**

## 2. 기존 플러그인 기능 → 웹에서의 처리

| 기존 기능 (플러그인) | 지금 동작 | 웹에서 | 이유 |
|---|---|---|---|
| **홈 타일** 책·논문·기사·유튜브·아이디어·커스텀 | 타일 → 모달 | **유지** (매체 모드 타일). 아이디어 타일은 삭제 → 진입 화면 덤프가 대신함 | 유튜브·아이디어는 플러그인에서 미구현이었음 |
| **덤프 모드 체크박스** | 켜야 덤프로 시작 | **삭제.** 덤프가 기본이자 유일한 방식 | 선택지 자체가 부담 |
| **책 입력 필드** 제목*·저자*·발간일·읽은 날·구조·별점·한 줄 소감 | 모두 모달에 노출 | 제목만 필수. 저자·날짜는 선택(접어두기). 별점·소감은 삭제 또는 맨 아래 선택 | 입력 전 장벽 최소화 |
| **책 구조 6종** 지식나열·인과·비교·주장-근거·이항대립·문학 | 사용자가 라디오로 선택 | **숨김 → AI가 판단** (이미 API가 `canvas_type`을 고름). 6종은 화면 레이아웃 템플릿으로만 씀 | 사용자는 구조를 고를 필요 없음 |
| **문학 분석 관점** 3종 체크 | 문학 선택 시 모달 | **숨김 → AI 판단** | 같은 이유 |
| **논문 필드** 제목*·저자*·연도·저널·DOI·읽은 날·한 줄 정리·구조 4종·속성 추가 | 모두 노출 | 제목만 필수. DOI/링크 넣으면 메타데이터 자동 채움(추후). 구조 4종은 AI 판단. 속성 추가는 삭제 | 같은 이유 |
| **기사 필드** 제목*·URL*·매체명·읽은 날·한 줄 정리 | 모두 노출 | URL만 넣으면 제목·매체 자동(추후). 수동 입력은 선택 | 같은 이유 |
| **덤프 마커** `??` `?!` `?*` | 사용자가 기호를 외워 직접 입력, 줄 색칠 | **사용자에게서 삭제.** AI가 자연어 속 망설임("~였던 것 같은데", "뭐였더라", "기억 안 남")에서 직접 감지 | 기호 암기는 부담. 감지는 AI의 일 |
| **분석 노드 4종** concept·loss·error·check | 캔버스 색으로 구분 | **사용자에게는 2가지 신호로 합침** (§3) | 4종 구분은 사용자에게 의미 없음 |
| **Canvas 고정 배치** (원본 왼쪽, 개념 한 줄, 문제 노드 아래 한 줄) | 옵시디언 캔버스 파일 생성 | **웹에서 직접 렌더링.** AI가 고른 구조 템플릿 레이아웃 사용 | 옵시디언 포맷 불필요 |
| **dump_locked + 재독/추가 영역** | 분석 후 원본 잠금, 아래에 추가 작성 | **유지(핵심).** 원본 덤프는 "그때 내가 알던 것"으로 보존, 이후 공부는 업데이트 층으로 쌓음 (§4) | 메타인지의 기준점 |
| **개념 노드** 연관 단어·설명·다시보기·각주·confidence | 사용자가 커맨드로 생성, 섹션 직접 관리 | **백엔드 자동.** 구조 속 개념은 자동으로 노드가 됨. 다시보기 = 신호 목록, 각주 = 자동 역링크, confidence = 자동 계산 | 사용자 관리 불필요 |
| **confidence** certain / partial / uncertain (마커 개수 기준) | frontmatter | **백엔드 유지**, 계산 기준을 신호 개수로 변경. 우주 뷰 표시에 활용 가능 (§6) | |
| **핵심 페이지로 저장** | 커맨드 → 노드를 .md로 승격 | **삭제.** 웹에서는 노드를 누르면 그 노드 페이지가 바로 열림 | 커맨드 개념 불필요 |
| **IRAC 5단계** 쟁점→상수→변수→전개(접속어)→결론(잠정 여부) | 모달 5개 연속 | **숨김.** ① AI가 "규칙 적용형" 내용이면 IRAC 레이아웃으로 구조화 ② 5개 질문은 달 에이전트가 필요할 때 대화로 안내 | 법학 공부엔 유용, 모달은 부담 |
| **ANT** 행위자 입력 → 행위자별 상수·목표 | 모달 + 캔버스 | **숨김.** AI가 "여러 주체가 얽힌" 내용이면 행위자 레이아웃으로 구조화 | 같은 이유 |
| **빠른 실행** 빈 페이지·개념 노드·ANT·IRAC | 홈 버튼 4개 | **삭제.** 진입 화면 덤프 하나로 대체 | |
| **가이드 뷰** (커맨드 설명) | 별도 화면 | **삭제.** 외울 커맨드가 없어짐 | |
| **테마** cozy / vivid | 설정 | 크림(기본) / 다크로 교체 | |
| **API 키 입력** | 사용자가 설정에 직접 입력, 기기 저장 | **삭제. 서버가 보관·호출.** | 보안, 사용자 부담 |

## 3. 사용자가 보는 신호는 딱 두 가지

| 사용자 화면 | 내부 노드 타입 | 의미 |
|---|---|---|
| **잘못 알았을 수 있어요** | `error` | 사실 오류 의심, 논리 모순 |
| **더 공부해 볼 곳** | `loss` + `check` | 맥락 공백, 흐릿한 내용, 구조 공백, 외부 확인 필요 |

- 기호 대신 **색 + 짧은 라벨**로 표시 (색만으로 구분하지 않음).
- 신호마다 "왜 그런지" 한 줄 이유를 붙인다 (기존 프롬프트 규칙: *WHY it's a gap/error* 유지).
- 사용자는 신호에 **"이건 맞아요"로 반박**할 수 있다 → 신호 해제, 기록은 남김. (AI도 틀린다. 판단 주체는 사용자)

## 4. 업데이트 루프 (새로 설계)

1. **덤프 원본은 잠긴다.** "이때의 나"로 보존. 수정 불가, 언제든 다시 볼 수 있음.
2. 구조 화면에서 신호가 붙은 노드를 누르면 → 그 자리에 **"알게 된 것 적기"** 입력칸.
3. 적은 내용은 원본을 덮지 않고 **업데이트 층**으로 붙는다 (날짜 포함).
4. AI가 업데이트를 다시 확인 → 해결됐으면 신호가 꺼지고 노드에 "업데이트됨" 표시. 아직 부족하면 이유와 함께 유지.
5. 막히면 달 에이전트에게: 학습이 필요하면 학습을, 정리가 필요하면 IRAC식 질문 등으로 돕는다.

→ 시간이 지나면 한 노드에서 **"처음 알던 것 → 고친 것"** 이 보인다. 이게 Moons가 보여주는 성장이다.

## 5. 구조화 규칙 (백엔드 / 프롬프트)

**"보정 없는 구조화"를 프롬프트에 명시해야 한다.** 현재 프롬프트에는 이 제약이 없다.

- 노드 텍스트는 **사용자 문장을 그대로** 쓰거나 최소한으로 줄인다. AI가 내용을 보태거나 매끄럽게 고치지 않는다.
- 빠진 부분은 AI가 채우지 않고 **빈 자리**로 남긴다 → 그 자리가 "더 공부해 볼 곳".
- 틀린 부분은 고치지 않고 **신호만** 단다. 정답은 사용자가 공부해서 채운다.
- 구조 유형(6종 + IRAC + ANT)은 AI가 고르고, 화면에서 **"다른 구조로 보기"** 로만 바꿀 수 있게 한다(선택, 강요 아님).

**응답 스키마 제안 (기존 확장)**

```jsonc
{
  "structure": "지식나열|인과구조|비교구조|주장-근거|이항대립|문학|IRAC|ANT",
  "nodes": [
    {
      "id": "n1",
      "text": "사용자 문장 그대로",
      "role": "concept|cause|claim|reason|actor|issue|...",   // 레이아웃 슬롯
      "source": [3, 4],            // 덤프 원문의 몇 번째 문장에서 왔는지
      "empty": false               // true = 사용자가 쓰지 않은 빈 자리
    }
  ],
  "edges": [{ "from": "n1", "to": "n2" }],
  "signals": [
    { "node": "n2", "kind": "misunderstanding|study", "reason": "왜 그런지 한 줄" }
  ],
  "suggested_planets": ["로준"]   // 우주 뷰 태그 제안 (사용자 확정)
}
```

- 기존 `loss/error/check` → `signals.kind`로 정리.
- `source`를 넣어서 "이 신호가 내 덤프의 어느 문장에서 왔는지" 화면에서 바로 짚어줄 수 있게.
- 기존 제한(노드 최대 12개, 노드당 60자)은 유지 여부 결정 필요. 보정 없는 구조화라면 글자 제한은 완화해야 할 수 있음.

## 6. 화면과의 연결

| 단계 | 화면 (UI 명세 참조) |
|---|---|
| ① 적기 | S1 진입-덤프 / S3 매체 페이지 |
| 접수 | S4 RECEIVED 도장 → 로딩 |
| ② 구조 + ③ 신호 | **S6 구조 화면 (신규)**: 사용자 말로 된 구조도, 신호 노드는 색+라벨, 화면 한쪽에 "잘못 알았을 수 있어요 N · 더 공부해 볼 곳 N" |
| ④ 업데이트 | S6에서 노드 → 업데이트 입력 → 재확인 |
| 누적 | S5 우주 뷰: 노드가 태그(모행성)로 쌓임 |

**우주 뷰에 쓸 수 있는 값**: 노드별 confidence와 신호 개수. 스케치의 모행성 파랑 진하기를 "해결 안 된 신호 비율"로 쓰면 크기(양)와 색(선명도)이 각각 의미를 가진다. — 제안이며 결정 필요.

## 7. 결정이 필요한 것

- [ ] 신호를 두 가지(잘못 알았을 수 있어요 / 더 공부해 볼 곳)로 확정할지
- [ ] 사용자가 신호를 반박(해제)할 수 있게 할지 — 권장
- [ ] AI가 고른 구조를 사용자가 바꿀 수 있게 할지("다른 구조로 보기")
- [ ] 별점·한 줄 소감을 남길지 버릴지
- [ ] 노드 개수·글자 제한 유지 여부
- [ ] 진입 화면의 그냥 덤프(매체 없음)도 같은 구조화를 거칠지, 메모로만 쌓였다가 나중에 묶어서 구조화할지
- [ ] IRAC 질문 안내를 에이전트 대화로 옮기는 것에 동의하는지
