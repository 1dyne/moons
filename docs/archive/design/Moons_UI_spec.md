# Moons 웹 — UI 명세 v0.1 (Codex 핸드오프용)

> 함께 첨부할 것: 로고 원본 이미지 1장, 화면 스케치 7장(아래 §1 표의 파일).
> 스케치는 **레이아웃·구성·색의 기준**이고, 렌더링 스타일(손떨림 선, 손글씨)을 따라 하라는 뜻이 아니다.

---

## 0. 디자인 원칙 (가장 중요)

1. **생산성 공간이다.** UI, 글씨, 입력되는 내용은 모두 깔끔하고 정갈하게. 장식·손글씨체·과한 일러스트 금지.
2. **귀여움은 캐릭터에만.** 로고와 달 에이전트(눈 두 개 달린 파란 달)만 귀엽고, 나머지는 절제한다.
3. **로고와 캐릭터는 원본 그대로 쓴다.** 다시 그리거나 비율·선·색을 바꾸지 않는다. 벡터화가 필요하면 원본 위에 겹쳐 비교해 차이가 없을 때만 교체한다.
4. **기본 테마는 크림(cosmic latte) 바탕**, 다크 모드는 선택 옵션.
5. 손그림의 굵은 검은 외곽선은 깔끔한 일정 두께 선으로 번역한다(아래 토큰 참조).

| `1000107226.jpg` | 우주 뷰(메인) | S5 |

**만들어야 할 파생 에셋**

- **달 에이전트 버튼**: 로고 속 달(파란 원, 오른쪽 짙은 반달 그림자, 눈 두 개)을 원형으로 떼어낸 버전. 지름 64–80px. 스케치 우하단 참조. 로고와 같은 선·색 유지.
- **모드 토글 아이콘 2개** (40–46px 정사각, 모서리 8px)
  - 행성 아이콘 = 덤프 모드
  - 세 칸이 쌓인 아이콘 = 매체 모드
  - 활성: 검은 바탕 + 흰 선 / 비활성: 흰 바탕 + 검은 선
- **망원경 아이콘** (검색창 오른쪽 끝)
- **RECEIVED 도장**: 파란 단색 원형 도장, 안쪽에 RECEIVED 글자. 약간 기울어짐(-15°)
- 아이콘은 모두 같은 선 두께의 라인 아이콘으로 통일. 이모지 금지.

## 2. 디자인 토큰

> 색 값은 스케치에서 추출한 근사치다. 실제 구현 전 다인 확인 필요(§5 질문 참고).

### 색

| 토큰 | 값 | 쓰임 |
|---|---|---|
| `--bg` | `#FFF8E7` (cosmic latte) | 기본 배경 |
| `--surface` | `#FFFFFF` | 입력창, 종이 카드 |
| `--ink` | `#1E1E1E` | 외곽선, 본문 글자 |
| `--ink-muted` | `#8A8A8A` | 플레이스홀더, 보조 글자 |
| `--moon` | `#7BA4F8` | 로고 달, 주요 강조, SEND 버튼 |
| `--moon-shade` | `#3B66BE` | 달 그림자, 도장 |
| `--arch` | `#F2E4D4` | 로고 아치, + 버튼 바탕 |
| `--chip` | `#EADFD0` | 입력창 칩, 검색창 바탕 |
| `--neutral` | `#E6E6E6` | 회색 원, 원형 보조 버튼 |
| `--teal` / `--teal-deep` | `#4BB59B` / `#0A93A6` | 로고 덤불(로고 외 사용 자제) |

**매체 타일 색 (택1 — 미정)**

| 매체 | 블루 세트 | 웜 세트 |
|---|---|---|
| 책 | `#D2E0F6` | `#CDB59F` |
| 논문 | `#E2D9F3` | `#E6DCCB` |
| 유튜브·팟캐스트 | `#D9EEE3` | `#F2DDD9` |
| 기사 | `#C6E8EA` | `#F7D2B6` |

규칙: **매체 페이지 전체 배경 = 해당 타일 색.** (책 페이지 스케치의 하늘색이 이 규칙)

### 글꼴

- 한글·영문 모두 **Pretendard** (대체: 시스템 산세리프). 손글씨체 사용 금지.
- 본문 16–18px / 줄간격 1.6, 입력 텍스트 18px, 제목 28–40px, 보조 14px.

### 형태

- 외곽선: `1.5–2px solid var(--ink)`로 통일 (손그림의 굵은 선을 깔끔하게 번역).
- 입력창: 완전한 알약형(`border-radius: 9999px` 또는 높이의 절반).
- 매체 타일: 세로가 약간 긴 둥근 사각형에 좌우가 살짝 볼록한 통(barrel) 느낌. 구현 예: `border-radius: 36% / 22%`. 과하게 일러스트처럼 만들지 말 것.
- 버튼 터치 영역 최소 44px.

## 3. 화면별 명세

### 공통 레이아웃 — 진입 헤더
- 화면 상단 중앙: **말풍선 → 로고** 순.
- 말풍선: 흰 바탕 사각형 + 얇은 외곽선, 꼬리가 아래쪽 로고를 가리킴. 로고 중심보다 약간 오른쪽에 위치.
- 로고 폭: 데스크톱 약 280px, 모바일 약 200px.
- 로고 아래 여백 후, 왼쪽 정렬로 **모드 토글 2개**, 그 바로 아래 **입력 영역**(S1의 입력창 또는 S2의 타일 줄).

### S1. 진입 — 덤프 모드 (기본 화면)
- 말풍선: "Ready to dump?"
- 입력창: 알약형, 최대 폭 약 800px, 여러 줄 입력(높이 약 160–170px, 내용에 따라 늘어남).
- 입력창 하단 왼쪽: `+` 원형 버튼(첨부 — 이미지/파일, 추후), 그 옆 베이지 칩 1개(용도 미정 — §5).
- 입력창 하단 오른쪽: 원형 버튼 2개(음성 입력 — 추후, 보내기).
- Enter = 보내기, Shift+Enter = 줄바꿈.
- 보낸 내용은 **생각 메모로 저장**(메모장처럼 가볍게). 보낸 뒤 입력창은 비워지고, 짧은 확인 피드백만.

### S2. 진입 — 매체 모드
- 말풍선: "Got some material?"
- 입력창 자리에 **매체 타일 가로 줄**: 책 / 논문 / 유튜브·팟캐스트 / 기사 / (AI) + 끝에 `+`(사용자 매체 추가).
- 타일 크기 약 150×150, 간격 약 24–40px. 라벨은 가운데, `--ink-muted` 색.
- 타일 클릭 → 해당 매체 페이지(S3)로 전환. 전환 시 배경이 타일 색으로 차오르는 짧은 전환(300ms 내외) 권장.

### S3. 매체 페이지 (예: 책)
- 전체 배경: 해당 타일 색.
- 가운데 **흰 종이 카드**(폭 약 480–560px), 위쪽은 반듯, **아래쪽은 지그재그로 찢어진 가장자리**(= 아래로 계속 이어 쓸 수 있음).
- 카드 상단: 큰 제목 입력("책제목" 플레이스홀더) + 그 아래 가로 구분선.
- 구분선 아래: 매체별 메타 정보 칸, 이어서 본문(덤프) 입력.
  - 책: 저자, 출판일, 읽은 날, (구조 유형)
  - 논문: 저자, 연도, 구조(실증 / 이론·논증 / 리뷰·비교 / 법학·정책)
  - 기사·영상: 출처, 날짜 등 — 기존 옵시디언 플러그인 필드 기준으로 정리
- 본문 안내 문구(플레이스홀더): "책 덮고, 기억나는 대로 적어보세요. 순서도 문장도 상관없어요."
- 오른쪽 아래 고정: **달 에이전트 버튼**.
- 이미지·파일 삽입은 추후 확장.

### S4. 보내기 → 접수
- 카드 하단 오른쪽 `SEND` 버튼(알약형, `--moon` 바탕, 외곽선).
- 누르면: 카드가 위로 밀려 올라가 **위쪽이 찢어진 상태**가 되고(영수증이 뜯긴 느낌), **RECEIVED 도장이 찍히는 연출**.
  - 도장: 크기 1.3 → 1.0, 약 250ms, 착지 시 아주 약한 흔들림.
- 이어서 짧은 로딩 → **사용자가 이해한 대로의 글 구조 정리 결과**(S6, 미설계)로 이동.

### S5. 우주 뷰 (메인)
- 배경: `--bg`, 장식 없음.
- **모행성 = 원 하나 = 분류 기준.** 원 안에 이름(예: 개발, 로준, 창작).
  - 크기: 태그된 노드 수에 따라 자동 증가. 면적 비례(반지름 ∝ √개수), 최소·최대 지름 제한.
  - 노드(덤프·매체 기록)는 태그로 모행성에 붙고, 현재 선택한 뷰의 모행성 기준으로 보인다.
- 회색 작은 원: 의미 미정(§5).
- 오른쪽 위: 알약형 검색창(`--chip` 바탕) + 망원경 아이콘.
- 오른쪽 아래: 달 에이전트 버튼.
- **배치**: 모행성은 사용자가 끌어다 놓는다(거리 = 사용자가 느끼는 주제 간 근접도). 노드만 모행성 주위에 자리 잡는다. 화면 전체가 계속 움직이는 물리 시뮬레이션은 쓰지 않는다(이전 MVP의 흔들림 버그 원인).
- **영역 표시(2단계)**: 연결선 대신 모행성마다 옅은 영역. 두 모행성에 동시에 태그된 노드가 많을수록 두 영역이 겹치거나 이어져 보이게.
- **근접도 알림(2단계)**: 사용자가 모행성 배치를 기준값으로 저장 → 실제 공동 태그 패턴이 기준과 어긋나면 알림. 수용 여부는 사용자가 결정.

### 공통 — 달 에이전트
- 모든 화면 오른쪽 아래 고정.
- 누르면 현재 화면 맥락을 가진 대화 패널(형태 미정 — §5).
- 역할: 단순 QA가 아니라 학습이 필요하면 학습을, 생각 정리가 필요하면 정리를 돕는 에이전트.
- 대화 중 원하는 메시지를 골라 Moons에 노드로 넣을 수 있게(가능 범위 확인 필요). 저장 시 **내가 쓴 말과 AI가 쓴 말은 구분해서 저장**.

## 4. 데이터 모델 (초안)

```ts
type Node = {
  id: string;
  kind: "dump" | "media" | "agent_clip";
  mediaType?: "book" | "paper" | "video_podcast" | "article" | "ai" | string;
  title?: string;
  meta?: Record<string, string>;   // 저자, 출판일 등
  body: string;
  authorRole?: "user" | "ai";      // agent_clip일 때 필수
  tags: string[];                  // 모행성 태그
  attachments?: string[];          // 추후
  createdAt: string;
};

type Planet = {                    // 모행성
  id: string;
  name: string;
  tag: string;
  viewId: string;
  position: { x: number; y: number };  // 사용자가 놓은 자리
};

type View = { id: string; name: string; planetIds: string[] };

type ProximityBaseline = {         // 근접도 기준값 캡처
  viewId: string;
  capturedAt: string;
  positions: Record<string, { x: number; y: number }>;
};
```

## 6. Codex 작업 요청 순서 제안

1. 로고 배경 투명 처리 + 달 에이전트 원형 크롭 에셋 (원본 변형 금지)
2. 아이콘 3종(행성 토글, 스택 토글, 망원경) + RECEIVED 도장
3. 디자인 토큰을 CSS 변수로 정의
4. S1 → S2 → S3 → S4 정적 화면
5. S5 우주 뷰 정적 화면(모행성 배치·크기 규칙만)
6. 이후 §5 결정에 따라 인터랙션 추가
