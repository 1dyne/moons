# v7 비용 예측서 (2026-10-24, 2판)

> **이 문서의 숫자는 측정값이 아니라 추정이다.** 1판(같은 날)은 출력 토큰을 약 5배 크게 잡아 논문 한 편을 gpt-5.4 기준 5.7달러로 냈다. 2판에서 고쳤다.
> 실제 값은 `ai_calls` 기록(명세 6.6)으로 잰다. 측정이 나오면 이 문서를 측정값으로 바꾼다(아래 5장).

## 1. 1판에서 틀린 곳

| 항목 | 1판 | 2판 | 이유 |
|---|---|---|---|
| 논문 한 편에서 뽑는 명제 수 | 약 1,300개 | 300~500개 | 핵심 명제만 뽑으면 충분 |
| 단계마다 얹은 추론 토큰 | 약 1천 | 출력의 약 20% | 낮은 effort 기준 |
| 재시도 | 모든 단계 30%를 비싼 모델로 | A~C 20% | 재시도는 실패한 단계만 |
| 개념 페이지 | 개념마다 따로 호출 | 10개씩 묶어 호출 | 같은 시스템 프롬프트 반복 제거 |
| 캐시 | 0 | 0 (그대로) | 품질 기준 통과 전 최적화 금지(6.5). 실제로는 더 싸게 나온다 |

## 2. 동작 하나당 토큰 (2판 추정)

| 동작 | 입력 / 출력 (천 토큰) |
|---|---|
| 짧은 자료 구조화 (1,000자) | 20 / 7 |
| 긴 자료 구조화 (논문 1편, 영어 8천 단어 또는 한국어 4만 자) | 165 / 55 |
| 덤프 구조화 (1,000자) | 16 / 6 |
| 비교 (문장 층 + 구조 층 + 다음 탐색) | 12 / 4 |
| 대화 노트 정리 (20턴) | 14 / 3 |
| 대화 1턴 | 6 / 0.6 |

## 4. 월 비용 (원, 추정)

가정은 1판과 같다. 운영자 R&D: 하루 짧은 자료 5, 논문 1, 덤프 10, 비교 10, 대화 노트 3, 대화 50턴 × 22일. 베타 10명: 1인 하루 짧은 자료 2, 논문 0.3, 덤프 3, 비교 3, 대화 노트 1, 대화 20턴 × 15일.

| 모델 | 운영자 R&D | 베타 10명 | 골든 평가 1회 |
|---|---|---|---|
| gpt-5.4-mini | 약 5.4만 | 약 12만 | 약 4천 |
| gpt-5.4 | 약 18만 | 약 41만 | 약 1.5만 |
| Claude Sonnet 5.5 | 약 13만 | 약 30만 | 약 1.1만 |
| Claude Opus 5.5 | 약 26만 | 약 60만 | 약 2.1만 |
| Gemini 2.5 Flash | 약 2.7만 | 약 6만 | 약 2천 |
| Gemini 3.1 Pro | 약 14만 | 약 33만 | 약 1.2만 |

골든 평가 1회 = 짧은 자료 6 + 논문 2를 3번씩. 베타가 운영자보다 큰 건 10명 × 15일 = 150 사용자-일이라서다.

## 5. 측정으로 바꾸는 방법

1. 운영자 계정으로 설정 → AI 모델에서 단계마다 모델을 고른다.
2. 같은 자료(논문 1편, 짧은 자료 2개, 덤프 1개)를 모델을 바꿔 구조화하고 비교한다.
3. 설정 → AI 모델 아래 "최근 30일" 표에 단계·모델별 호출 수, 토큰, 비용이 쌓인다. 이 값으로 2~4장을 다시 쓴다.
4. 품질은 같은 노트의 분석 기록(모델별)을 나란히 보고 판단한다. 9.2 지표는 골든 세트가 들어오면 `scripts/eval-structure.mjs --model`로 잰다.

구조화 v3(M3)는 단계가 더 나뉘므로, M3 구현 뒤 다시 한 번 측정한다.
