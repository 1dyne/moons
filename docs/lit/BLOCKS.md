# lit 블록 구조: 로직은 lit이, 의미와 모양은 사용자가

> 2026-11-11 설계 + 1차 구현. 2026-11-12 새 에디터(화면 · 동작 · 저장 칸, 규칙 카드, 상황, 스티커, 움직임, 개발자 콘솔)로 고침.
>
> **쓰는 말:** 화면에는 개발자 말 대신 DB · 항목 · 속성 · 부품 · 규칙 · 상황만 쓴다. 예전 문서의 "기록 묶음"은 DB, "블록"은 부품, "자동화"는 규칙이다. 동작 단어(verb)는 데이터에 남지만 화면에서 고르지 않는다. 이 문서는 "lit이 로직을 제공하고, 사용자는 이름·연결·디자인을 바꿔 자기 위젯을 만든다"는 구조의 설계도이자, 지금 코드가 어디까지 왔는지의 기록이다.

## 0. 왜 바꾸나

지금까지 lit의 위젯(수면, 집중 타이머, 신호등, 소원 상자…)은 **기능 하나에 위젯 하나**를 코드로 만든 것이었다. 그래서:

- 버튼 → 타임스탬프 기록이라는 같은 로직이 수면·타이머·체크마다 따로 있었다.
- 사용자가 만든 속성(표의 열, 할 일 속성)은 이름과 값만 있고 시스템이 읽지 않았다(보이기만 하는 구조).
- 기상/취침 버튼을 뽀모도로로 바꾸는 것처럼 **같은 로직을 다른 의미로 쓰는 것**이 불가능했다.

새 구조에서 lit은 **로직 블록**을 빠짐없이 제공하고, 사용자는 블록을 골라 위젯을 조립하고 이름을 붙인다. 노션이 DB를 먼저 만들고 그 안에서 쓴다면, lit은 **쓰고 싶은 위젯을 먼저 놓고 쓰면서 확장한다.**

## 1. 세 층

```
[데이터]  기록(entry): 타입 · verb · 시각 · 값 · 속성 · 연결      ← 사람과 AI가 같이 읽는다
   ↑↓
[로직]    타입(기록 묶음) · 블록 · 자동화 (TypeScript, 화면과 서버가 같은 코드)
   ↑↓     위젯이 주고받는 데이터 계약
[디자인]  블록 그대로 + 디자인 토큰  |  HTML·CSS 템플릿  |  코드 위젯(SDK)
   ↓
[페이지]  위젯 배치 = 내 미니홈피
```

세 가지 사용자 행동이 층과 그대로 맞는다.

| 사용자 | 직접 만드는 것 | 받아 쓰는 것 |
| --- | --- | --- |
| 1. 로직부터 짠다 | 타입·블록·자동화 + 디자인 | – |
| 2. 디자인만 바꾼다 | 디자인(토큰, HTML·CSS) | lit 기본/판매 로직 위젯 |
| 3. 템플릿을 산다 | (배치만 조정) | 로직 + 디자인 + 배치 + 예시 타입 묶음 |

## 2. 데이터 문법 (사람과 AI가 같이 읽는 기록)

한 줄 = "언제, 무엇이, 어떤 결과로". 학습 기록 표준 xAPI(행위자·동사·대상·결과·시각)와 같은 생각이다.

```json
{
  "kind": "entry",
  "logicalDay": "2026-11-11",
  "body": {
    "type": "sleep",
    "verb": "did",
    "at": "2026-11-10T15:10:00Z",
    "end": "2026-11-10T22:05:00Z",
    "value": {"amount": 415, "unit": "분"},
    "fields": {"q": 4},
    "links": [{"rel": "part_of", "to": "01J…목표 id"}]
  }
}
```

| 칸 | 뜻 | 누가 정하나 |
| --- | --- | --- |
| `type` | 기록 묶음 id (수면, 집중…). 이름·설명은 타입 정의에 | 사용자 |
| `verb` | 고정 단어집 8개: planned · started · ended · did · measured · felt · wished · noted | 시스템 (사용자가 고름) |
| `at` / `end` | 시각(시간대 포함). end가 있으면 길이가 있는 기록 | 블록 |
| `value` | 숫자 + 단위. 합계·평균이 맞으려면 단위가 있어야 한다 | 블록/타입 단위 |
| `fields` | 사용자 속성. 키는 속성 id라 이름을 바꿔도 데이터가 안 깨진다 | 사용자 |
| `links` | 다른 기록과의 관계: part_of(목표의 일부) · for(페르소나) · after(이어서) · about(관련) | 연결 속성/자동화 |

**타입 정의** (`spec.logic.types`): `id · name · desc · icon · unit · fields[]`. 속성마다 `name · kind · desc · unit · options · max · to`.
속성 종류: 숫자 · 점수 · 짧은 글 · 긴 글 · 선택 · 여러 개 선택 · 체크 · 날짜 · 시각 · 걸린 시간 · 연결.
**`desc`(한 줄 설명)가 AI가 그 칸을 이해하는 열쇠다.** 노션 "메모" 속성 설명("1.사건 2.신체 신호 3.생각")이 하던 역할.

내보내기(메뉴 → 로직 → 내보내기)는 타입 사전 + 기록을 한 줄에 하나씩(JSON Lines) 준다. 같은 형태를 커넥터가 AI에게 준다.

코드: `lib/life-contract/src/records.ts` (`EntryBody`, `VERBS`, `LINK_RELS`), `lib/planner-spec/src/logic.ts` (`TypeDef`, `FieldDef`).

## 3. 로직 블록 (전부 갖추고, 이름만 사용자가)

| 갈래 | 블록 | 하는 일 |
| --- | --- | --- |
| 입력 | 버튼 | 누르면 그 시각 한 줄 (기상, 약 먹음) |
| | 시작·끝 버튼 | 시작 → 끝, 길이가 남음 (취침→기상, 운동) |
| | 카운터 | +1마다 한 줄, 하루 목표 (물, 커피) |
| | 오늘 체크 | 그날 했는지 (습관) |
| | 점수 | 1~N (기분, 컨디션) |
| | 입력 칸 묶음 | 고른 속성을 채워 저장 (독서, 지출, 일기). 연결 속성은 추천 후보를 띄움 |
| 시간 | 스톱워치 | 흐르는 시간을 보이는 시작·끝 |
| | 타이머 | 단계(집중 25 → 휴식 5)를 이어 반복, 단계가 끝날 때마다 한 줄 + 알림 |
| 계산 | 숫자·게이지 | 개수·합계·평균·최대·최소·연속 일수·기록한 날·마지막 값, 목표 대비 %, 숫자/게이지/원/막대 |
| 보기 | 목록 · 표 · 카드 · 시간축 · 달력 · 막대 차트 | 기간·정렬·조건·보일 속성·필터 칩 |
| 꾸미기 | 제목·문구 · 빈 줄 | |

모든 블록은 같은 타입의 기록을 읽고 쓴다. 블록 설정은 `LogicBlock` 스키마 하나로 검증되므로 **스키마에 없는 설정은 존재할 수 없고, 있는 설정은 모두 코드가 실행한다.**

예시 틀(프리셋)도 블록으로만 만든다. 열어서 무엇이든 바꿀 수 있다.

- **기존 위젯을 블록으로** (2026-11-11 이전): 집중 타이머(과목별), 10분 타임테이블, 하루 영수증, 오늘의 미션, 오늘의 나, 에너지 신호등, 오늘의 루틴, 하루 돌아보기, 수면(기상·취침).
  과목·루틴 항목은 사용자가 이미 쓰던 것(타이머 위젯의 과목, 루틴 기록)으로 채운다. 지어내지 않는다.
- **새로 만들기:** 빈 위젯, 뽀모도로, 물 마시기, 독서 기록, 습관 체크, 지출, 소원 해금.

이를 위해 더한 블록 기능: 시작·끝 버튼/체크를 선택 속성으로 **항목별 행**(과목별 타이머, 루틴 항목), 끝나면 **점수 묻기**(컨디션), 숫자의 **신호등** 모양(파랑·빨강 기준 + 점수별 메시지, 폰은 i 버튼), **나눠 보기**(과목별 시간, 원형/막대), **10분 타임테이블** 블록.

### 잰 시간은 10분 타임테이블에 저절로

`timeStretches()` 하나가 타이머 세션과 "끝이 있는(또는 지금 재는) 기록"을 모두 모은다. 10분 타임테이블 블록(범위: 잰 시간 전부 / 이 묶음만)과 **기존 10분 타임테이블 위젯** 둘 다 이것을 읽으므로, 어느 위젯으로 재든(집중 타이머 블록, 시작·끝 버튼, 뽀모도로, 수면) 칸이 저절로 칠해진다.
같은 과목은 어느 타이머로 쟀든 같은 색(타이머 위젯에서 정한 과목 색)이다. 타입에 `focus`가 켜진 묶음(집중)은 영수증·폰 요약의 순집중에 더해진다(수면은 아님).

### 예전 기록 가져오기

`from`이 있는 타입(집중 ← 타이머 세션, 수면 ← 수면, 컨디션 ← 컨디션 점검)은 메뉴 → 로직에서 예전 기록을 한 번에 복사해 온다. 원본은 그대로 두고(목표 진행률·분석이 계속 읽음), 복사본은 `ext.src`로 원본을 기억해 두 번 가져와도 늘지 않으며, 타임테이블·영수증은 같은 시간을 두 번 세지 않는다.

코드: `logic.ts` (`LOGIC_BLOCKS`, `LogicBlock`, `aggregate`, `periodRange`), `artifacts/planner/src/made/MadeWidget.tsx`, `made/presets.ts`.

## 4. 위젯 사이 연결 (사용자가 고른다)

| 통로 | 무엇 | 언제 정하나 |
| --- | --- | --- |
| ① 같은 타입 | 두 위젯이 같은 기록 묶음을 쓰면 한쪽 기록이 다른 쪽에 바로 보인다 (기상 버튼 ↔ 평균 수면 숫자) | 스튜디오 → 데이터 → 기록 묶음 고르기 |
| ② 관계 | 연결 속성으로 기록 ↔ 기록 (독서 → 목표). links에 part_of로도 남아 AI가 읽는다 | 데이터 → 속성 종류 "연결", 대상 고르기 |
| ③ 계산 | 숫자·차트 블록이 묶음을 세고 더한다 (롤업) | 블록 설정 |
| ④ 자동화 | 어느 위젯에서든 기록이 생기거나 바뀌면 → 조건 → 동작 | 연결·자동화, 메뉴 → 로직 |
| ⑤ 맥락 | 페이지에서 고른 날짜(주간 띠, ‹ ›)를 따라간다 (`followDay`) | 기본 켜짐 |

속성에 고정된 것은 "종류"뿐이다(연결 속성은 어떤 기록을 가리킨다). 연결할지는 사용자가 정하고, 템플릿은 미리 연결된 채로 온다.

### 규칙 (언제 → 만약 → 하기 → 효과)

규칙은 색 카드 줄로 보이고(스크래치·Shortcuts 방식), 같은 규칙을 코드(JSON)로 바꿔 볼 수 있다. 카드의 칸은 전부 목록에서 고르므로 엔진이 못 도는 규칙은 만들 수 없다. 카드 아래에는 같은 규칙이 한 문장으로 보인다(조사까지 맞춘다: "소원의 항목마다, 그 항목의 조건이 되면 · 상태가 잠김이면 → 상태를 열림으로, 그 카드에 반짝 효과, 알림 "{이름} 열렸어요"").

| 카드 | 색 | 무엇 |
| --- | --- | --- |
| 언제 | 노랑 | DB에 항목이 생기거나 바뀌면(record) · **항목마다 그 항목의 상황이 되면(item)** · **상황이 되면(signal)** · 매일 정한 시각(time) · 하루 시작(dayStart) · 일어났어요(wake) |
| 만약 | 주황 | 그 항목의 속성 조건(if) · **상황 조건(when: 순집중 8시간 이상, 할 일 다 끝냄, 에너지 4 이하…)** · 합계 조건(ifAgg) |
| 하기 | 파랑 | 항목 추가 · 그 항목 고치기 · 조건에 맞는 항목 고치기 · 알림 · 화면 띄우기(영수증·아침 상태) |
| 효과 | 보라 | 움직임 재생: 반짝 · 통통 · 흔들 · 둥실 · 두근 · 빙글 · 톡 · 빛남 · 축하 (그 카드에 / 위젯 전체에) |

```
on:    {kind, type, event, field, signal}   field = item 규칙이 읽는 상황 속성, signal = signal 규칙의 상황
if:    [{field, op, value}]                 when: [Signal]      ifAgg: [{type, agg, of, period, op, value}]
do:    create | update | updateWhere | notify | open | effect   (최대 8개)
```

**상황(Signal)** (`planner-spec/src/signals.ts`): lit이 모든 기록에서 계산하는 사용자의 지금 — 오늘 순집중 n시간 · 오늘 할 일 다 끝내기 · 정한 시각 전에 다 끝내기 · 끝낸 할 일 n개 · 오늘의 미션 · 목표 진행률 n% · 목표 이루기 · 에너지 n 이상/이하 · DB 합계. `evalSignal`은 {충족, 지금 값, 목표 값, "3:20 / 8:00"}을 돌려줘 카드의 진행 막대에도 쓴다. 속성 종류 **상황**은 항목마다 상황 하나를 담는다(소원마다 다른 여는 조건).

- **실행:** record 규칙은 서버에서 모든 쓰기 뒤에(`api-server/src/life/flows.ts`). item 규칙은 서버(모든 쓰기 뒤, Claude가 쓴 기록이어도)와 열린 플래너(기록이 바뀔 때마다) 둘 다에서 돌고, 같은 항목은 baseRevision으로 한 번만 바뀐다. 서버가 연 항목은 화면이 알아보고 알림·효과를 한 번 보여 준다. signal·시각·하루 시작·기상은 열린 플래너가 하루 한 번.
- 고리 방지: 규칙이 쓴 기록에는 그 규칙 id가 사슬로 붙고, 한 사슬에서 같은 규칙은 두 번 돌지 않으며 6단계에서 멈춘다. 새 기록 판정은 `createdAt === updatedAt`.
- 위젯 ⚙의 "하루 시작에 어제 영수증" 같은 설정도 규칙을 만든다(메뉴 → 로직 → 규칙에 보인다).

### 연결 추천 (일정을 적으면 목표가 떴던 것의 정체)

기존 할 일 위젯은 제목을 두 글자씩 잘라(언어이해 → 언어·어이·이해) 오늘 걸린 목표 제목과 겹치는 조각이 2개 이상이면 가장 많이 겹치는 목표를 골랐다(짧은 기간 목표 우선). 문자열 비교라 같은 단어가 있을 때만 떴다.
새 `suggestLinks`는 연결 속성이 있는 모든 입력에 쓰이고, ① 예전에 비슷한 제목을 어디에 연결했는지(사용자 선택에서 배움) ② 글자 유사도 순으로 후보를 띄운다.

## 5. 보기와 필터

- **기간:** 보이는 날 · 오늘 · 이번 주 · 최근 7일 · 이번 달 · 최근 30일 · 전체 (날이 바뀌어도 따라간다)
- **항상 거는 조건:** 블록 설정의 조건 (속성 · 비교 · 값)
- **필터 칩:** 사용자가 이름 붙인 조건 묶음. 위젯 위에 칩으로 뜨고 한 번 눌러 바꾼다. 어떤 칩을 둘지 사용자가 정한다. 고른 칩은 기기에 기억된다.

## 6. 에디터 (어디서, 어떻게 만드나)

- **들어가기:** 메뉴 → 위젯 만들기 (예시 틀 고르기) / 만든 위젯을 두 번 누르기 / ⚙.
- **세 칸 + 미리보기:** 넓은 화면은 오른쪽에 **실제 기록으로 도는 미리보기**(폰 모양), 폰은 탭.

| 칸 | 무엇 |
| --- | --- |
| **화면** | 보이는 방식(펼쳐 두기 / 스티커) · 부품(갈래별 팔레트, 순서, 부품마다 움직임과 언제: 누를 때·나타날 때·계속) · 꾸미기(컬러 차트 7종 → 직접 색·모양 → HTML·CSS → 개발자 콘솔) |
| **동작** | 이 위젯의 DB에 걸린 규칙 카드들 + "+ 규칙". 규칙마다, 또 전체를 코드로 볼 수 있다 |
| **저장 칸** | 이 위젯의 DB: 새로 만들기 / 기존 DB 고르기(= 다른 위젯과 연결), 이름·설명·단위·속성(글·숫자·선택·점수·연결·상황…) |

**메뉴 → 로직:** 모든 DB(속성·설명·항목 수·쓰는 위젯)와 모든 규칙을 한곳에서. 켜고 끄기, 고치기(같은 규칙 카드), 내보내기.

### 스티커 (게임 UI 같은 아이콘 버튼)

위젯 전체가 페이지에 스티커로 붙고, 누르면 아래에서 올라오는 시트 / 가운데 팝업 / 새 페이지로 열린다(뒤로가기로 닫힌다). 스티커 모드의 위젯은 카드 테두리·제목 없이 놓인다.

- **칼선 스티커:** 아이콘 모양 그대로, 흰 칼선 테두리와 그림자.
- **도형 아이콘:** 원 · 둥근 네모 · 별 · 하트 · 구름 · 라벨 안에 아이콘.
- **내 이미지:** 올린 그림(360px로 줄여 저장). 투명 PNG면 모양대로 칼선, 아니면 원·하트·별·구름으로 따기.
- 크기 · 기울기 · 이름표 · **숫자 배지**(항목 수, 또는 "상태: 열림"인 항목 수).

### 꾸미기의 네 수준

| 수준 | 누구 | 무엇 |
| --- | --- | --- |
| 컬러 차트 · 효과 예시 | 모두 | 종이·민트·하늘·복숭아·베리·밤·계기판 팔레트, 부품 움직임 9종 |
| 토큰 | 모두 | 강조·배경·글자 색, 모서리, 간격, 정렬, 부품 모양, 아이콘 |
| HTML · CSS | 디자인만 바꾸는 사람 | 템플릿 + CSS(@keyframes 가능). 부품은 그 안에서도 그대로 동작 |
| 개발자 콘솔 | 개발자·LLM | HTML · CSS · JavaScript를 그대로. 격리 iframe에서 돌고 `window.lit.made`로만 lit에 닿는다 |

**개발자 콘솔 API:** `await lit.made.data()` → `{title, entries:[{id, time, 값, 속성 이름…}], blocks}` · `lit.on('change', d => …)` · `lit.made.press(부품id)` · `lit.made.add({속성 이름: 값})` · `lit.made.update(항목id, {…})`. 인터넷 접속은 막혀 있고(CSP), 웹 표준 API와 묶어 올린 라이브러리는 쓸 수 있다. 규칙은 서버가 그대로 돌리므로 콘솔 위젯도 규칙·상황을 같이 쓴다.

**템플릿 문법** (`planner-spec/src/template.ts`): `{{이름}}` (이스케이프), `{{a.b}}`, `{{#each 목록}}…{{else}}…{{/each}}`, `{{#if x}}…{{else}}…{{/if}}`, `{{icon "moon"}}`. `{{{raw}}}`는 금지.
부품 넣기: `<lit-block ref="부품id"></lit-block>`, 부품 버튼 동작: `data-lit-press="부품id"`.
값: `title · desc · day · today · entries[] (time·end·duration·value·unit·속성 이름) · last · blocks.<id>`.

**아이콘:** Lucide(ISC) 중 100여 개를 lit에 묶어 둔다. 외부 요청 없음.

**보안:** 템플릿 결과에서 script·iframe·form·style 태그, on* 속성, 외부 주소를 지운다. CSS는 @import·외부 url()을 지우고 모든 선택자를 그 위젯 아래로 가둔다. 개발자 콘솔은 sandbox iframe(allow-scripts만) + CSP.

### 예: 소원 상자 (새 에디터의 첫 예시 틀)

- 저장 칸: 소원 DB = 소원(글) · 여는 조건(상황) · 상태(선택: 잠김 · 열림 · 사용함)
- 화면: 칼선 선물 스티커(배지 = 열림 수, 누르면 시트) · 부품 = 입력 칸 묶음(소원, 여는 조건) + 열림 카드(조건·진행 막대·사용하기·다시 잠그기)
- 동작: ① 소원에 항목이 추가되면 · 상태가 비어 있으면 → 상태를 잠김으로 ② 소원의 항목마다, 그 항목의 조건이 되면 · 상태가 잠김이면 → 상태를 열림으로, 그 카드에 반짝, 알림 "{이름} 열렸어요"

## 8. 꾸러미와 마켓

**꾸러미(`planner-spec/src/pack.ts`):** 만든 위젯 하나 = `{contract, title, desc, options, types, flows}`. 위젯의 DB, 그 규칙이 쓰는 DB, 그 DB들에 걸린 규칙, 화면(부품·스티커·꾸미기·콘솔 코드)이 들어가고 **기록과 목표는 들어가지 않는다**(상황의 목표 지정도 비운다).

- **위젯 계약 버전(`LOGIC_CONTRACT`, 지금 1):** options·DB·규칙의 뜻이 바뀌면 올린다. 앱보다 새 계약의 꾸러미는 설치하지 않고 "앱을 새로 고친 뒤 설치"라고 알린다. 예전 계약의 꾸러미는 스키마 기본값으로 채워져 그대로 돈다.
- **설치(`installPack`):** 같은 id·같은 속성 모양의 DB가 있으면 그 DB를 같이 쓴다(기록이 바로 보인다). 모양이 다르면 새 id로 들인다(`wish` → `wish2`)고 규칙·상황·합계 조건의 DB id도 함께 바꾼다. 이미 있는 똑같은 규칙은 다시 넣지 않는다.
- **코드 승인:** 꾸러미에 개발자 콘솔 코드가 있으면 그 코드의 지문(codeHash)을 사용자가 승인해야 그려진다(코드 보기 → 승인하고 켜기). 사용자가 에디터에서 콘솔 코드를 고쳐 저장하면 그때부터 자기 코드라 승인이 필요 없다.
- **나누는 길:** 에디터 → 화면 → 나누기(라이브러리에 저장 / 파일로 내보내기 `.lit.json`) · 메뉴 → 내 라이브러리(꾸러미 파일 가져오기, 오늘 페이지에 넣기, 파일로) · 커넥터 `share_widget`/`install_widget`.
- **판매 단위:** 로직 위젯(꾸러미), 디자인(토큰/HTML·CSS, 같은 계약 위), 템플릿(전부 + 배치). 검수 기준: 라이선스 표기(MIT·ISC 키트 허용, 유료 키트 재판매·기존 서비스 디자인 복제 불가), 폰 미리보기 통과, 콘솔 코드는 승인 게이트.
- **결제:** 돈을 받는 창구는 결제사(PG) 계약과 사업자 정보가 있어야 열 수 있다. 꾸러미·계약 버전·승인·설치는 결제와 상관없이 지금 그대로 쓰고, 결제사가 정해지면 라이브러리 저장 앞에 결제 확인 한 단계가 붙는다.

| 우려 | 대응 |

## 11. 모드 (상황에 따라 바뀌는 데일리 플래너)

`spec.modes`: 이름, 켜지는 때(오늘 마지막 에너지 ≤ N, 없으면 직접 켤 때만), 할 일 방식, 전용 페이지(선택).

- **에너지:** 컨디션 점검, 타이머 멈출 때 남긴 컨디션, 컨디션 묶음의 점수 중 오늘 가장 최근 값(`currentEnergy`).
- **한 일 방식(`did`, 에너지 긴축모드):** 끝나지 않은 할 일은 모두 **희망사항**(회색)으로 보이고, 하면 **한 일**(색칠 + 시각)로 바뀐다. 새로 적는 것은 바로 한 일로 저장된다. 요약·집계는 "한 일 N". 할 일 자체(분류·계획)는 바꾸지 않으므로 모드가 꺼지면 원래대로다.
- **전용 페이지:** 모드마다 두 번째 데일리 템플릿을 둘 수 있다(메뉴 → 모드 → 전용 페이지 만들기 → 꾸미기).
- **직접 바꾸기:** 오늘 페이지 위 모드 줄에서 끄기 / 켜기 / 에너지로 정하기. 그날 하루만, 그 기기에만 적용된다.
- 커넥터: `set_modes`, `get_planner`의 `modes`.
