> 브랜치 `claude/festive-galileo-7mzcbq`. 기존 코드(`artifacts/moons`, `api-server`)는 참조만 하고 새 앱으로 만든다.
> 제품 이름은 앞으로 소문자 **moons**.
> 이 문서는 "LLM 없이 되는 범위"를 먼저 정하고, LLM이 붙을 자리(편향 감지·감정)는 설계만 열어 둔다.

## 00. 화면이 답할 질문 (2026-11-15, 다인 확정 — 이 문서의 다른 내용보다 우선)

| 탭 | 답할 질문 |
|---|---|
| **기록** | 내가 가장 편하게 쓸 수 있는 페이지 형태와 도구로 기록한다. 기록은 LLM도 이해할 수 있는 개념 단위로 저장되어, 사용자가 실제로 아는 것과 모르는 것을 알 수 있다 |
| **학습** | 기록된 페이지들을 폴더처럼 묶어 한 페이지 안에 배치한다. 설정만 바꿔서 Top-down(전체 개념 지도)과 각 부분의 개념 암기(Bottom-up)를 한다 |
| **Space** | 내가 moons에 저장한 아는 것과 관심 가졌던 것을 모행성으로 본다. 요즘 자주 생각해서 정보가 많이 쌓인 행성일수록 크고, 최근 학습한 내용은 빛나서 요즘 어디에 관심이 있는지 보인다 |

탭 구성은 v9 그대로(기록 · 학습 · Space · 공유, 추가한 Satellite는 하단). 이후 장의 My Space 설계(3.5)는 이 표에 맞춰 다시 쓴다.


### 정보는 쓰다 보면 저절로 쌓인다 (2026-11-16 확정)
- moons는 사람이 쓰는 개인 DB이면서, **AI가 사용자를 이해하기 위해 읽는 지식 베이스**다. 같은 데이터를 둘 다 읽는다.
- 사용자에게 한 번에 채우게 하지 않는다. 정보는 세 길로 들어온다.
  1. **쓰는 동안 저절로**: 저장, 고침, 다시 보기, 테스트 결과, 걸린 시간, lit 생활 데이터, Satellite 기록
  2. **사용자가 먼저 말할 때**: 일기·페이지·대화에 쓴 말("나 조건문 약한 것 같아", "다음 달 시험")을 moons가 목표·자기 믿음·조건으로 읽어 둔다. 외부 AI와 나눈 대화도 커넥터로 들어온다
  3. **moons가 물을 때**: 꼭 필요한 순간에 한 가지만, 건너뛸 수 있게. 예: 같은 방식으로 세 번 틀렸을 때 "이번엔 어떻게 봤어?", 새 모행성이 생겼을 때 "목표가 있어?" 쓰기를 막지 않고, 같은 질문을 반복하지 않는다
- 가장 좋은 건 1, 2다. 3은 1, 2로 알 수 없을 때만.
- moons가 사용자에 대해 알게 된 것은 **사용자가 볼 수 있고 고치거나 반박할 수 있는 형태**로 둔다(열린 학습자 모델). AI 커넥터도 같은 내용을 읽는다.

## 0. 한 문장

**moons는 한 사람이 아는 것·생각한 것을 쌓아 두는 개인 DB이고, 사람은 그 DB를 "요즘 내가 무슨 생각을 하고, 안다고 착각한 게 뭔지" 보는 화면으로, LLM은 같은 DB를 구조 그대로 읽는 자료로 쓴다.**

이전 설계에서 그대로 가져오는 원칙 (v6 0장, v7 2장):

| 원칙 | moons next에서 |
|---|---|
| 원문을 고치지 않는다 | 스파크·일기는 "보내기" 후 잠기고, 이후 생각은 **업데이트 층**으로 붙는다. 카드·페이지는 고칠 수 있지만 고친 전/후가 전부 기록된다 |
| 층을 섞지 않는다 | 모든 내용에 `layer: user / material / ai`. 지금 단계는 전부 `user`·`material` |
| 판정하지 않는다 | "틀렸어요" 대신 관찰: "확신했는데 3번 중 2번 틀렸어요" |
| 고르는 건 사용자 | 정리·배치·색의 의미는 사용자가 정한다 |
| 화면에 설명 문구 없음 | v7 0장 7항 유지 |

## 1. 입력 종류 — 이전 설계에서 가져온 것

이전 설계(아카이브 기능정리 v0.1 → v6 폼 → v7 노트 종류 → v8.1 단어 카드)에 있던 입력을 정리하고, 이번에 새로 필요한 카드·테이프를 더했다.

| 종류 | 화면 이름 | 이전 설계 출처 | 내용 | moons next |
|---|---|---|---|---|
| `spark` | 스파크 | v7 `Entry.kind='dump'` | 생각나는 대로 덤프. 보내면 잠기고 업데이트 층이 쌓인다 | 유지. 일기·아이디어 끄적임도 여기로(아래 `diary` 템플릿) |
| `material` | 자료 노트 | v7 `kind='media'`, UI 명세 S3 | 책·논문·기사·영상·직접 추가. 제목만 필수, 저자·날짜는 접어 둠 | 유지. 본문은 "자료를 보고 내가 쓴 것" |
| `page` | 페이지 | v6 폼 | 블록으로 쓰는 노트. **템플릿 = 폼**. 코넬은 내장 템플릿 하나 | 신규 이름. 폼 개념을 그대로 씀(4장) |

| `sentence` | 문장 | 이번 요청(spoil your appetite) | 한 줄 문장. 뒷면(뜻·상황)은 선택 | 카드의 한 종류(`cardKind:'sentence'`) |
| `term` | 용어 페이지 | v7 개념, v8.1 term | 개념 하나의 페이지. 내 말로 쓴 정의, 연결된 카드, 이 말이 나온 페이지들 | 유지. 등장 위치는 글자 맞추기로 자동(v8.1 `terms.ts` 매처 재사용, LLM 불필요) |
| `memo` | 메모 | v7 `memos` | 어디에나 붙이는 포스트잇. 원문 아님 | 유지. 캔버스 빈 곳에도 붙일 수 있음 |
| `chat` | 대화 노트 | v7 `kind='chat'` | MOONS 대화에서 만든 노트 | LLM 단계에서 |
| `record` | 활동 기록 | v8 Satellite | 외부 학습 도구 결과 | 나중(기존 MCP와 합칠 때) |

**덤프 마커 / 구조 6종 / IRAC·ANT**: 이전 설계에서 "AI가 판단, 사용자에겐 숨김"으로 결정됐다. LLM 없는 단계에서는 **페이지 템플릿**으로만 제공한다(코넬, 오답노트, 비교표, IRAC). 사용자가 직접 고른다.

**확신도** (v6 5.2): "지금 이걸 남에게 설명할 수 있다고 얼마나 확신해요?" — 1~10을 따로 고르게 하지 않고, 테스트 모드의 **뒤집기 전 예측**(3.3)으로 대신 받는다.

## 2. 카드

### 2.1 구조
```
┌ go by ─────────────── ▮ ┐   ← ▮ = 인덱스 테이프 (색 + 선택 메모)
│                         │
│   did you move here     │   ← 앞면. 글자 일부에 형광펜
│        [did] 빨강        │
│                    👁   │   ← 이 카드의 형광펜 보이기/숨기기
└─────────────────────────┘
         ⟲ 뒤집기
┌─────────────────────────┐
│   [과거] 빨강             │   ← 뒷면. 같은 색 = 사용자가 정한 짝
└─────────────────────────┘
```
- 면(Face)은 **글자** 또는 **손글씨**, 둘 다 섞어도 된다(5장).
- 카드 종류: `basic`(앞/뒤) · `term`(단어: v8.1의 원형·품사·뜻·콜로케이션·주의점 칸) · `sentence`(한 줄, 뒷면 선택) · `choice`(선택형 문제).
- **선택형 카드** `choice` (2026-11-16 추가)
  - 앞면: 문제 + 보기. 양자선택(O/X, 2지)부터 5지선다까지. 보기 순서 섞기는 선택.
  - 뒷면: 정답 + 풀이. 보기마다 "왜 틀렸나" 한 줄을 달 수 있다(선택).
  - 테스트에서 고른 보기를 그대로 기록한다. **어떤 오답 보기를 골랐는지**가 틀리는 방식의 흔적이 된다(예: 범위를 넓힌 보기를 반복해서 고름).
  - 뒤집기 전 예측(알 것 같아 / 모르겠어)은 다른 카드와 같이 적용된다.
  - 보기에도 형광펜·👁 규칙이 같이 적용된다.

### 2.2 형광펜
- 기본 팔레트 6색(빨강·주황·노랑·초록·파랑·보라). 색의 의미는 사용자가 정한다. 원하면 설정에서 색마다 이름을 붙인다(예: 빨강 = 시제 단서). 이름은 선택이고, 비어 있으면 색만 보인다.
- 글자 면: 글자 범위에 칠한다(`start`, `end`, `color`). 원문 글자는 바뀌지 않는다.
- 손글씨 면: 형광펜 획(반투명 레이어)으로 칠한다.
- 👁 **카드별 스위치** + **전체 스위치**(상단 바). 전체를 끄면 모든 카드에서 숨겨지고, 전체를 켠 상태에서는 카드별 설정이 적용된다.
  - 전체 = 끔 → 모두 숨김
  - 전체 = 켬 → 카드별 👁에 따름 (기본 켬)
- 테스트 모드에서는 뒤집기 전 형광펜 보이기를 따로 정할 수 있다(앞면 단서까지 숨기고 싶을 때).

### 2.3 인덱스 테이프
- 형광펜과 별개. 카드 가장자리에 붙는 작은 색 띠. 한 카드에 여러 개 가능.
- 테이프 팔레트(형광펜과 같은 6색 + 회색). **색마다 범례 메모**(설정에서 "초록 = 몰랐던 카드")와 **테이프 하나하나의 메모**(이 카드에 왜 붙였는지)를 둘 다 남길 수 있다. 둘 다 선택.
- 테이프는 필터가 된다: Bottom-up에서 "초록 테이프만 넘기기".
- 테스트에서 틀린 카드에 테이프를 자동으로 붙이는 옵션(기본 끔). 사용자가 쓰던 "몰랐던 카드 = 초록" 습관을 자동화할 수 있게.

## 3. 화면과 사용자 흐름

### 3.0 원칙 — 들어올 이유, 빠르게, 한눈에
1. **열자마자 할 일이 하나 보인다.** "오늘 털 카드 7장" 같은 2~3분짜리. 다 하면 끝. 숙제 목록처럼 쌓이지 않게 하루 최대치를 둔다.
2. **로딩 없음.** 전부 기기 안(IndexedDB)에 먼저 저장하고 화면은 즉시 뜬다. 서버 동기화는 뒤에서.
3. **화면은 셋뿐.** My Space(홈) · 지도(Top-down ⇄ Bottom-up) · 어디서나 뜨는 `+` 입력.

### 3.1 전체 흐름
```
            ┌──────────── + 입력 (어디서나) ────────────┐
            │ 카드 · 문장 · 스파크 · 페이지 · 자료 · 메모 │
            │ 지금 보고 있는 폴더에 들어감               │
            │ My Space에서 누르면 "아직 안 놓은 것"으로   │
            └──────────────────┬───────────────────────┘
                               ▼
 ┌──── My Space (행성 지도) ────┐          ┌──────── 지도 ────────┐
 │ 달 + 숫자 ───────────────────┼────────▶ │ Bottom-up · 테스트   │
 │ 크레이터 누르기 ─────────────┼────────▶ │ (털 것 / 착각한 것)  │
 │                              │          ├──────────────────────┤
 │ 행성 누르기 = 확대해 들어감 ─┼────────▶ │ Top-down (캔버스)    │
 └──────────────────────────────┘          │  ⇅ 알약 버튼          │
                                           │ Bottom-up · 보기     │
                                           └──────────────────────┘
```

### 3.2 지도 — Top-down
- **하나의 끝없는 캔버스.** My Space 행성 지도에서 확대해 들어온 곳이다. 폴더(모행성)는 캔버스 위의 **제목 묶음(프레임)**이고, 하위 폴더는 그 안에 들어 있거나 점선으로 이어진다. 경로는 상단에 `TEPS / LC / 관용`.
- **확대 단계에 따라 보이는 것이 달라진다** (의미 확대):
  - 멀리: 폴더 제목 + 항목 수 + 먼지 정도
  - 중간: 항목 제목(카드 앞면 첫 줄)
  - 가까이: 카드 전체·형광펜·테이프, 바로 편집
- 끌어서 옮기기(항목·폴더), 점선 연결 그리기, 빈 곳 두 번 누르면 그 자리에 `+`.
- **왜소행성**(아직 안 놓은 것): 모행성 없이 넣은 항목은 캔버스 가장자리 더미에 쌓이고, 끌어다 놓으면 모행성이 정해진다.
- 폴더 하나 = 위치 하나(트리). 다른 폴더에도 보여야 하면 **참조**(링크 카드)를 놓는다.

### 3.3 지도 — Bottom-up
- 알약 버튼으로 전환. 가운데 큰 영역에 항목 하나, 오른쪽에 **축소 지도 + 지금 위치 표시**(노란 동그라미), 상단에 경로.
- 범위: 지금 고른 폴더와 그 아래 전부. 테이프·종류 필터.
- 순서: **캔버스 배치 순서**(폴더 → 위에서 아래, 왼쪽에서 오른쪽) · **만든 순서** · **무작위** — 사용자가 고르고 기억된다. 테스트 모드에는 **보완 우선**이 추가된다.
- 모드 두 가지:

| | 보기 | 테스트 |
|---|---|---|
| 목적 | 훑어보며 공부 | 아는지 확인 |
| 카드 | 앞뒤 자유롭게 뒤집기, 형광펜은 👁 설정대로 | 앞면만 → 뒤집기 |
| 표시 | 선택: 테이프 붙이기, "몰랐음" 한 번 누르기 | ① 뒤집기 전 **예측**: `알 것 같아` / `모르겠어` ② 뒤집은 후 **결과**: `맞았어` / `틀렸어` (스킵 가능) |
| 기록 | `view` 이벤트(먼지 털림) | `review` 이벤트(예측·결과·걸린 시간) |
| 문장·페이지 | 그대로 읽기 | 문장은 앞/뒤가 있으면 카드처럼, 페이지는 보기만 |

- **예측 + 결과 = moons의 핵심 신호.**
  - `알 것 같아` + `틀렸어` → **착각한 앎** (안다고 생각했는데 모른 것)
  - `모르겠어` + `맞았어` → **숨은 앎** (생각보다 아는 것)
  - 예측 단계는 설정에서 끌 수 있다. 꺼도 결과만으로 복습 간격은 돈다.
- 복습 간격(LLM 불필요): 상자 5칸(1·3·7·14·30일). 맞으면 다음 칸, 틀리면 첫 칸. 착각한 앎은 첫 칸 + "착각" 표시가 2번 연속 맞을 때까지 남는다.

### 3.4 페이지 쓰다가 카드·용어 만들기
- 페이지·스파크·자료 본문에서 글자를 고르면 작은 도구 막대: `형광펜` · `카드로` · `용어로` · `메모`.
- `카드로` → 앞면 = 고른 글자, 뒷면 비움, 출처(어느 페이지 어느 문장)가 연결된다. **뒷면이 빈 카드**는 My Space "채울 것"에 보인다.
- `용어로` → 용어 페이지 생성(이미 있으면 연결만). 이후 다른 글에 같은 말이 나오면 자동으로 밑줄(v8.1 매처: 대소문자·활용형·구 처리).
- 용어 페이지에는 **내 말로 쓴 정의**가 있는지 표시. 없으면 v7의 **왜소행성**과 같다(쌓였지만 내 말로 설명한 적 없음).

### 3.5 My Space — 화면 전체가 내 생각 지도

> 2026-11-14 수정: 글 대시보드 대신 **행성 지도 하나**로 바꿨다. 원래 의도(UI 명세 S5 우주 뷰, v9 Space 우주 보기)대로 모행성으로 정보를 나눈다. 글은 거의 없고, 정보는 모양으로 읽힌다.

**같은 것을 부르는 이름 정리** (v9 명세 `claude/moons-usability-feedback-e7mrxv` 기준)

| moons next | v9 이름 | 뜻 |
|---|---|---|
| 폴더 | **모행성** | 분류. 상하 계층(`parentId`). 하위는 상위 색 계열 안에서 밝기만 다름 |
| 아직 안 놓은 것 | **왜소행성** | 모행성이 없는 항목. 지도 바깥 띠에 작은 점으로 떠 있다 |
| 내 말 정의 없는 용어 | **설명 전** | 쌓였지만 내 말로 설명한 적 없음 |
| 착각한 앎 | **크레이터** | 안다고 했는데 틀림(v9: 확신 − 실제 ≥ 50) |
| 숨은 앎 | **별 ✦** | 생각보다 앎(v9: 실제 − 확신 ≥ 25) |

**디자인 원칙 — 기능을 모양으로** (2026-11-15 확정)
1. 화면의 모든 모양은 데이터 하나에 대응한다. 대응하는 데이터가 없는 장식(지평선, 배경 연출, 보기 좋게 놓은 자리)은 넣지 않는다.
2. **색은 사용자가 모행성에서 고른다.** moons가 미리 정하지 않는다. 고르기 전에는 회색. 하위 모행성은 상위 색을 밝게 물려받고, 직접 고르면 그 색이 우선(v9 4.8).
3. **위치는 관련도로 계산한다.** 함께 묶인 기록이 많은 모행성끼리 가깝게 놓인다(한 기록이 여러 모행성에 속하는 수, 부모-자식 계층). 같은 데이터면 항상 같은 자리.
4. **무엇을 볼지는 필터로 정한다.** 기간 · 보기 필터 · 모행성 범위를 걸면 해당하는 행성만 진하게 남고 나머지는 흐려진다. 자주 쓰는 필터 조합은 저장된 보기(v9 7.1)로.
5. 움직임도 데이터가 바뀔 때만: 확대(위치 이동), 빛의 세기(활동량), 먼지(시간), 털기(복습).

**지도에서 읽는 법** — 범례는 `?`를 눌렀을 때만 보인다.

| 모양 | 데이터 | 답하는 질문 |
|---|---|---|
| 행성 사이 거리 | 함께 묶인 기록 수(가까울수록 많음) | 어떤 주제들이 내 안에서 이어져 있나 |
| 행성 사이 선 굵기 | 함께 묶인 기록 수. 점선 = 상하 계층 | 왜 가까이 있나 |
| 행성 크기 | 쌓인 기록 수 | 무엇을 많이 쌓았나 |
| 색 | 사용자가 고른 색, 안 고르면 회색 | 내가 나눈 분야 |
| 행성 둘레의 빛 | 고른 기간(1·7·30일)에 다룬 양 | **요즘 무슨 생각을 하나** |
| 먼지 → 거미줄 + 흐려짐 | 마지막으로 본 뒤 지난 날(카드는 상자 칸에 따라 속도가 다름, 3.6) | 무엇을 오래 안 봤나 |
| 크레이터(움푹한 구멍) | 착각한 앎 개수 | **안다고 생각했는데 모르는 것이 어디 있나** |
| ✦ | 숨은 앎 | 어디는 생각보다 잘 아나 |
| 숫자 배지 | 설명 전 개념 수 | 어디에 내 말로 못 하는 것이 쌓였나 |
| 바깥 띠의 점 | 왜소행성 | 정리 안 된 것이 얼마나 있나 |
| 오른쪽 아래 달 + 숫자 | 오늘 털 것 | 지금 할 것 하나 |

**필터**
- 기간: 1일 · 7일 · 30일 (빛의 세기가 바뀜)
- 보기 필터: 전체 · 요즘 · 착각 · 먼지 · 설명 전 (해당 행성만 진하게)
- 모행성 범위: 고른 모행성과 그 하위, 그리고 그것과 묶인 행성만 남기고 다시 배치

**사용자가 옮긴 자리**: 행성을 끌어 옮기면 그 자리를 "내가 느끼는 거리"로 저장한다(UI 명세 S5, v6 근접도). 계산된 관련도와 크게 어긋나면 알림만 준다("인지심리와 moons 설계는 멀리 두었는데 함께 묶인 기록이 6개예요"). 바꾸는 건 사용자.

**흐름**
1. 열면 지도만 보인다. 빛나는 행성 = 요즘 생각, 구멍 난 행성 = 다시 볼 곳, 먼지 낀 행성 = 오래 안 본 곳.
2. 달(숫자 배지)을 누르면 오늘 털 카드로 바로 테스트(3.3). 착각한 앎 → 복습할 때 → 먼지 많은 순, 최대 10장.
3. 행성에 마우스를 올리면 한 줄: `LC · 기록 21 · 착각 2 · 설명 전 3 · 오늘 봄`.
4. 행성을 누르면 함께 묶인 행성과 개수, 색 고르기, `들어가기`가 뜬다. `들어가기`를 누르면 그 행성으로 확대해 들어간다 = 지도의 Top-down(3.2). 다시 확대하면 하위 모행성 → 카드. My Space와 Top-down은 **같은 지도를 다른 높이에서 보는 것**이다.
5. 크레이터를 누르면 그 행성의 착각한 카드만 Bottom-up 테스트로 연다.

**지도에서 빠진 것과 그 자리**
- "생각이 바뀐 곳"(전/후 비교), "새로 알게 된 것", "채울 것" 목록은 홈에서 뺀다. 행성으로 들어가면 오른쪽 패널에 그 행성 것만 나온다.
- 기간 비교 숫자(+12 같은 것)도 빛의 세기로만 보인다.

### 3.6 먼지와 거미줄
- 모든 항목은 **마지막으로 만진 때**(보기·테스트·수정)를 가진다.
- 먼지가 쌓이는 속도 = 그 항목이 얼마나 단단한지. 상자 5칸에 있는 카드는 천천히, 1칸 카드는 빨리 쌓인다. 즉 **먼지 = 잊어 가는 정도의 그림**이다.

| 단계 | 기준(1칸 카드 / 5칸 카드) | 그림 |
|---|---|---|
| 깨끗 | 3일 / 30일 미만 | 그대로 |
| 먼지 조금 | ~7일 / ~60일 | 옅은 점, 채도 살짝 낮춤 |
| 먼지 많음 | ~21일 / ~120일 | 점 많아짐, 흐려짐 |
| 거미줄 | 그 이상 | 모서리에 거미줄 |

- 카드·문장이 아닌 것(스파크·페이지)은 상자가 없으므로 기본 속도(먼지 많음 30일, 거미줄 90일).
- 폴더 프레임의 먼지 = 안에 든 항목 평균. 멀리서 보면 "어느 주제를 오래 안 봤는지"가 보인다.
- **털기 조건은 사용자가 고른다** (설정 → 먼지, 모행성마다 다르게 둘 수 있음).

| 조건 | 털리는 때 | 어울리는 것 |
|---|---|---|
| 보기 | Bottom-up에서 넘겨 보면 | 가볍게 훑을 것 |
| 핵심 읽기 (기본) | 형광펜 칠한 부분과 뒷면을 끝까지 펼쳐 봐야. 페이지는 형광펜·요약 칸을 지나가야 | 개념·페이지 |
| 테스트 | 테스트에서 `맞았어`를 눌러야. 틀리면 먼지가 그대로 남고 복습 간격이 처음으로 | 시험 공부 카드 |

- 캔버스에서 먼지 낀 항목을 문지르면 그 조건이 바로 뜬다(핵심 읽기면 핵심 부분이 펼쳐지고, 테스트면 앞면이 뜬다). 조건을 마쳐야 먼지가 걷힌다. 문지르기만으로는 털리지 않는다.
- 다 아는 것까지 먼지로 혼나지 않게: 항목을 **보관**하면 먼지가 쌓이지 않는다(지도에는 흐리게 남음).

## 4. 페이지와 템플릿

- 페이지 = 블록 목록. 블록: `text` · `heading` · `list` · `checklist` · `table` · `ink`(손글씨 영역) · `embed`(다른 항목 카드 끼워 넣기).
- 템플릿 = v6의 폼. 내장 템플릿:
  - **코넬**: 단서(왼쪽 좁은 칸) | 필기(오른쪽) | 요약(아래). 단서 칸 한 줄을 고르면 `카드로` → 앞면 = 단서, 뒷면 = 같은 높이의 필기 칸 내용.
  - **오답노트**: 문제 / 내 답 / 정답 / 왜 틀렸나.
  - **비교표**: 항목 × 기준 표.
  - **IRAC**: 쟁점 / 규칙 / 적용 / 결론.
  - **일기**: 날짜 + 자유 서술(스파크와 같이 보내면 잠김).
- 사용자 템플릿 만들기는 v6 폼 빌더와 같은 방식(나중).

- 저장: 획 = 점 목록 `[x, y, 압력]`을 줄여서 저장. 카드 한 면 수 KB 수준.

## 6. 데이터 — LLM이 읽을 수 있는 개인 DB

### 6.1 두 층
1. **현재 상태**: 컬렉션들(아래). 지금 무엇이 있는지.
2. **이벤트 기록**: 지워지지 않는 추가 전용 기록. 무엇이 언제 어떻게 바뀌었는지. My Space의 모든 기간 계산과 "생각이 바뀐 곳", LLM의 "최근 변화 읽기"가 여기서 나온다.

기존 `lib/moons-sync`의 형식(id 있는 배열 = 컬렉션, `diff`/`apply` 연산)과 맞춰 두면 나중에 서버 동기화·MCP가 그대로 붙는다.

### 6.2 타입 (초안)
```ts
type Layer = 'user' | 'material' | 'ai';
type Color = 'red' | 'orange' | 'yellow' | 'green' | 'blue' | 'purple' | 'gray';

type Folder = { id: string; name: string; parentId: string | null;
  frame: { x: number; y: number; w: number; h: number };   // 캔버스 위 위치
  order: number; archived?: boolean; createdAt: string; updatedAt: string };

type Stroke = { tool: 'pen' | 'highlighter' | 'eraser'; color: string; width: number; points: number[] }; // x,y,p 반복
type Mark = { id: string; start: number; end: number; color: Color };        // 글자 범위 형광펜
type Face = { text: string; marks: Mark[]; ink?: Stroke[]; transcript?: { text: string; layer: Layer } };
type Tape = { id: string; color: Color; note?: string; auto?: 'wrong' };

type ItemBase = { id: string; folderId: string | null;   // null = 아직 안 놓은 것
  pos?: { x: number; y: number }; tapes: Tape[]; eye: boolean; archived?: boolean;
  source?: { itemId: string; start: number; end: number };  // 어디서 만들었나
  layer: Layer; createdAt: string; updatedAt: string; touchedAt: string };

type Card = ItemBase & { type: 'card'; cardKind: 'basic' | 'term' | 'sentence' | 'choice';
  choice?: { options: Face[]; answer: number[]; why?: (string | null)[]; shuffle?: boolean };   // 2~5개, 정답 여러 개 가능
  front: Face; back: Face; term?: { headword: string; pos?: string; meaningKo?: string; forms?: string[]; collocations?: string[]; pitfall?: string };
  srs: { box: 1 | 2 | 3 | 4 | 5; dueAt: string; illusion: number } };   // illusion = 연속 착각 해소 전까지 남은 횟수

type Block = { id: string; kind: 'text' | 'heading' | 'list' | 'checklist' | 'table' | 'ink' | 'embed'; slot?: string; face?: Face; rows?: string[][]; itemId?: string };
type Page = ItemBase & { type: 'page' | 'spark' | 'material' | 'question' | 'diary';
  title: string; template?: 'cornell' | 'wrong' | 'compare' | 'irac' | 'diary' | string;
  blocks: Block[]; lockedAt?: string;                         // 스파크·일기: 보내면 잠김
  updates?: { id: string; text: string; createdAt: string }[]; // 잠긴 뒤 업데이트 층
  meta?: { mediaType?: 'book' | 'paper' | 'article' | 'video' | 'custom'; author?: string; url?: string; publishedAt?: string };
  open?: boolean };                                           // 질문 노트

type Term = ItemBase & { type: 'term'; name: string; aliases: string[];
  definitions: { text: string; layer: Layer; ref?: { itemId: string } }[] };  // 내 말 정의 = layer 'user'
type Memo = ItemBase & { type: 'memo'; text: string; target?: { itemId: string } };
type Link = { id: string; from: string; to: string; kind: 'dotted' | 'source' | 'mentions' | 'ref'; createdAt: string };

type Event = { seq: number; at: string; device: string;
  type: 'created' | 'updated' | 'moved' | 'archived' | 'deleted' | 'viewed' | 'reviewed' | 'locked' | 'update_added';
  itemId: string; before?: unknown; after?: unknown;           // updated: 바뀐 필드만 전/후
  review?: { mode: 'test' | 'browse'; predicted?: 'know' | 'unsure'; result?: 'right' | 'wrong'; picked?: number[]; ms?: number } };

type Settings = { eyeAll: boolean; markNames: Partial<Record<Color, string>>; tapeLegend: Partial<Record<Color, string>>;
  order: 'canvas' | 'created' | 'random'; testOrder: 'canvas' | 'created' | 'random' | 'due';
  predictStep: boolean; autoTapeOnWrong?: Color; dailyMax: number };
```

### 6.3 LLM이 읽는 방식
- **내보내기 두 가지**: (1) `moons.json` — 위 컬렉션 + 이벤트 + `schema` 설명 한 덩어리. (2) Markdown 폴더 — 폴더 = 디렉터리, 항목 = `.md` 하나(맨 위에 YAML로 `id/type/folder/tapes/srs/createdAt/touchedAt`, 본문에 앞면/뒷면, 형광펜은 `==글자=={red}` 표기). 옵시디언에서도 그대로 열린다.
- 손글씨 면은 `transcript`가 있을 때만 글자로, 없으면 `[손글씨: 글자 없음]`.
- 나중에 기존 MOONS MCP(`search_notes`, `recent_activity` …)가 같은 DB를 읽는다. `recent_activity`는 이벤트 기록을 기간으로 자르면 된다.

## 7. 편향·논리 오류 알아차리기 (설계만, LLM 단계)

목표: 개념이나 주제에 대해 생각을 쓸 때 **한쪽으로 치우친 생각을 쓰는 순간 스스로 알아차리게** 한다. 판정이 아니라 관찰과 질문 하나.

### 7.1 대상
- 스파크·페이지·질문 노트 중 **주장이 들어 있는 문장**. 일기는 기본 제외(설정으로 켤 수 있음).
- 같은 주제(폴더·용어)에 쌓인 글 전체 — 한 문장보다 **시간에 걸친 패턴**이 더 중요하다.

### 7.2 단계
| 단계 | 방법 | 잡는 것 | LLM |
|---|---|---|---|
| A. 표현 신호 | 단어 목록 | 절대어(항상·절대·모두·다들·무조건·당연히·never·always), 감정 단정(최악·말도 안 되는) | 불필요 |
| B. 자료 균형 | DB 집계 | 한 주제에 연결된 자료가 한 출처뿐 / 반대 입장 자료 0개 / 스파크만 계속 쓰고 자료·질문 노트가 없음 | 불필요 |
| C. 정체 | 이벤트 | 새 자료를 넣어도 같은 주장이 몇 달째 그대로 | 불필요 |
| D. 주장 분석 | LLM | 문장별 주장 추출 → 아래 목록으로 분류, 근거 문장 인용 | 필요 |
| E. 과거의 나와 대조 | LLM | "3주 전 같은 주제에서는 반대로 썼어요" | 필요 |

- A~C는 LLM 없이 지금 설계 범위에서 만들 수 있다. 결과는 "알아차림" 카드로만 보이고, D는 A~C가 켜진 문장에만 돌려 비용을 줄인다.
- 기존 코드에 이미 주장 단위 평가가 있다(`DumpLayer.claims[].assessment: holds / questionable / unsupported`). D는 이걸 확장한다.

### 7.3 분류 목록 (작게 시작)
과잉 일반화 · 흑백 논리 · 한쪽 근거만(확증 편향) · 상관을 인과로 · 사례 하나로 결론 · 권위에 기댐 · 감정으로 추론 · 상대 주장 바꿔 치기(허수아비) · 미끄러운 비탈 · 결과 보고 원래 알았다고 함(사후 확신).

### 7.4 보이는 방식
- 그 문장 옆에 작은 표시. 누르면: 관찰 한 줄("'모두'로 묶었고, 든 사례는 1개예요") + 질문 하나("반대 사례가 있다면 뭘까요?") + `의도한 표현이에요`(끄기, 기록 남음).
- 사용자가 자주 끄는 분류는 그 사람에게 덜 보이게 한다.
- My Space에는 넣지 않고, 주제 쪽에만 "이 주제는 자료가 한쪽에서만 왔어요" 같은 B·C 관찰을 둔다(홈을 무겁게 만들지 않기 위해). 감정 설계 때 다시 정한다.

### 7.5 데이터
```ts
type Signal = { id: string; kind: 'bias'; type: string; itemId: string; range?: { start: number; end: number };
  evidence: string; question?: string; by: 'rule' | 'ai'; state: 'open' | 'dismissed' | 'resolved'; createdAt: string };
```

## 8. 감정 — 나중

- 사용자가 태그하지 않는다. **개념(용어·카드·주제)과 관련된 글에 감정이 들어 있을 때만** 분석한다.
- 기존 `Emotion {family, word, evidence, intensity}` 형태를 그대로 쓸 수 있다.
- 편향 설계(7장)와 이어질 수 있다: 감정이 강한 주제일수록 B·C 신호의 무게를 올리는 식. 나중에 함께 정한다.

## 9. 만드는 순서

각 단계가 끝나면 그 자체로 쓸 수 있어야 한다.

| 단계 | 내용 | 끝나면 할 수 있는 것 |
|---|---|---|
| N1 | 앱 뼈대(Vite + React), IndexedDB 저장, 이벤트 기록, 폴더 트리, `+` 입력, 카드(글자 면)·형광펜·👁(카드별·전체)·테이프 | TEPS 카드를 만들고 칠하고 테이프를 붙인다 |
| N2 | Bottom-up 보기: 순서 3가지, 필터, 넘기기 | 폴더 단위로 카드를 넘겨 본다 |
| N3 | Top-down 캔버스: 이동·확대, 폴더 프레임, 끌어 옮기기, 점선, 의미 확대, 안 놓은 것 더미 + Bottom-up 축소 지도 | 전체 구조도를 고치고, 공부 중인 위치를 본다 |
| N4 | 테스트 모드: 예측·결과, 상자 간격, 착각 표시, 자동 테이프, 먼지 | 아는지 확인하고, 먼지가 보인다 |
| N5 | My Space | 매일 들어와서 털고, 요즘 생각과 착각한 앎을 본다 |
| N6 | 페이지·스파크·자료·질문 + 템플릿(코넬 등) + `카드로`·`용어로` + 용어 자동 밑줄 | 페이지를 쓰며 모르는 말을 카드·용어로 쌓는다 |
| N7 | 손글씨 면(펜·형광펜 획·지우개) | 펜으로 카드를 만든다 |
| N8 | 내보내기(JSON·Markdown), 가져오기 | LLM·옵시디언이 읽는다 |
| 이후 | 서버 동기화(`moons-sync`), 기존 MCP 연결, 편향 A~C → D~E, 감정 | |
