# lit 전체 구조도 v1 (2026-11-16)

> 사용자의 큰 그림(A·C)을 받아 B·D~H를 채운 초안. 현재 기능 목록은 [INVENTORY_2026-11-16](INVENTORY_2026-11-16.md).
> **(예)** 가 붙은 것은 lit이 고정으로 만드는 기능이 아니라, 사용자가 lit 문법으로 만들 수 있는 **템플릿**이다.

---

## A. 한 문장

**lit은 사용자가 lit의 문법으로 자기가 편한 대로 DIY하는 자동화 플래너다.**

여기서 나오는 원칙 세 개:

1. **lit이 주는 것은 기능이 아니라 문법이다.** "에너지 신호등", "가용 시간 계산기", "성취 기록지"는 lit 기능이 아니다. 문법으로 조립한 템플릿이다.
2. **위젯은 사용자 데이터를 받는 창구다.** 배치도, 이름도, 메시지도 lit마다 다르다.
3. **모든 DB는 사용자 DB다.** 노션이 빈 페이지에서 시작하고 템플릿을 받아 쓰듯, lit도 빈 문법에서 시작한다. 하루 일과·목표는 플래너에 맞춰 **처음부터 깔려 오는 DB**일 뿐, 특별한 DB가 아니다. 일상관리 무엇이든 같은 문법으로 만든다.
4. **lit이 아는 것은 DB가 아니라 "속성 역할(Property role)"이다.** 이름 · 날짜 · 시작 · 끝 · 달성 · 고정 일정. 어느 DB든 이 역할을 붙인 칸이 있으면 타임테이블·진행률·충돌 확인 같은 계산이 그 DB에서도 돈다.
5. **문법 이름은 영어가 기본, 한국어는 번역이다.** 화면에 보이는 말은 전부 사용자가 고친다.

## B. 원본 데이터: 어디에 저장하나

### B-1. 답: 저장소는 하나, 칸은 세 갈래

저장 **위치**는 이미 하나다(서버의 기록 저장소 `life_records`). 정할 것은 위치가 아니라 **그 칸의 뜻을 누가 아느냐**다.

| 갈래 | 누가 뜻을 아나 | 예 | 바뀌면 |
|---|---|---|---|
| ① **역할이 붙은 칸** (Property role) | lit이 안다. 계산·자동화가 이 역할을 읽는다 | 이름(Title) · 날짜(Date) · 시작(Start) · 끝(End) · 달성(Done) · 고정 일정(Fixed) | 칸 이름·모양은 자유. 역할만 lit이 읽는다 |
| ② **사용자 칸** | 사용자가 만든다. lit은 종류(Number · Select · Time…)만 안다 | 페르소나, Role, 예상 시간, 못 한 이유, 에너지 점수 | 자유 |
| ③ **계산 값** (Formula · Aggregate) | 저장하지 않는다. 볼 때마다 ①②로 계산 | 목표 진행률, 가용 시간, 예상 대비 소요, 회색 여부 | 공식을 바꾸면 바로 반영 |

**규칙:** 같은 정보는 한 곳에만 저장한다. 다른 곳에 보이는 건 모두 보기다. 다른 기록을 복사해 두는 표(지금의 집중 로그·성취 기록지 등)는 만들지 않는다.

### B-2. 처음부터 깔려 오는 DB (플래너 기본 템플릿)

| DB | 역할이 붙은 칸 | 비고 |
|---|---|---|
| **하루 일과** (지금 이름: 할 일) | 이름 · 날짜 · 시작 · 끝 · 달성 · 고정 일정 | 하루 일과와 고정 일정은 같은 DB. 고정 일정은 칸 하나로 구분 |
| **목표** | 이름 · 기간 · 상태 · 진행률(계산) | 하루 일과와 연결하면 진행률이 생긴다 |

- **달성(Done)의 단계는 사용자가 정한다.** lit은 각 단계가 "끝냄 / 안 끝냄 / 세지 않음" 중 어디인지만 안다. (예) 한 일=끝냄, 일부=안 끝냄, 취소=세지 않음.
- 그 밖의 모든 것(페르소나, 루틴, 에너지, 수면, 운동…)은 사용자가 만들거나 템플릿으로 받는 DB다.

### B-3. 시간 기록 (Timestamp)

시간을 남기는 부품은 **사용자가 고른 DB의 시작·끝 역할 칸**에 쓴다. 따로 쌓이는 "세션 저장소"는 두지 않는다.
→ 10분 타임테이블(Time grid)은 시작·끝 역할이 있는 항목이면 어느 DB든 칠한다. 하루 일과에 시작·끝을 찍으면 그게 곧 소요 시간이다.

## C. 사용 상황 (사용자 원문 요약)

1. 하루 일과 → 중장기 목표 %로 집계 → 목표에서 달성 / 포기를 고름
   - 달성 → 축하 메시지 → 기록 / 포기 → 다독이는 알림 → 기록
   - 메시지와 기록 양식은 사용자가 정한다. lit은 "이런 구조가 가능하다"는 것만 준다
2. (예) 시간대별 에너지 신호등 → 고정 시간(식사·수면 등)을 뺀 가용 시간에 반영 → 실제로 쓸 수 있는 시간 계산
3. (예) 에너지·가용 시간으로 보면 못 할 일정은 희망사항으로 보내고 회색으로 표시. 이때 어떤 모양들이 가능한지 lit이 보여 주고 사용자가 고른다
4. lit이 기본으로 받는 것은 하루 일과와 고정 일정. 기능 말고는 이름을 전부 바꿀 수 있다
   - 기본 기록: 시간, 이름, 달성 여부. 체크 방식·시간 기록 방식·이름은 꾸밀 수 있다
   - (예) 10분 타임트래커와 이어서 할 일 옆에 소요 시간
   - 목표·페르소나 등 어떤 DB와 어떻게 이을지는 사용자의 몫
   - **할 일 추가·삭제·변경이 쉬워야 하고, 필터로 보고 싶은 것만 볼 수 있어야 한다**
5. lit이 주는 것은 공통 기능의 이름(예: [timestamp])이다. 비개발자는 lit 안에서 조립하고, 개발자는 디자인까지 바꾼다. 마켓은 구조가 정리된 뒤에 연다

## D. lit 문법 (lit이 제공하는 것 전부)

lit이 만들고 지키는 것은 이 표가 전부다. 새 기능 요청은 **이 표에 줄이 하나 더 생기는지**로 판단한다. 안 생기면 템플릿으로 만든다.
이름은 **English (한국어)**. 영어가 문서·AI·마켓에서 쓰는 기본 이름이고, 한국어는 화면 번역이다. 코드: `lib/planner-spec/src/grammar.ts`, 각 목록의 `en` / `name`.

| # | 문법 | 하는 일 | 지금 | 모자란 것 |
|---|---|---|---|---|
| **Store (저장)** |||||
| 1 | Database (DB) | 항목을 모으는 곳. 모두 사용자 DB | 있음 | 기본 DB(할 일·목표)가 아직 특별 취급 → §I |
| 2 | Property (속성) | 종류: Number · Rating · Text · Long text · Select · Multi-select · Checkbox · Date · Time · Duration · Relation · Signal | 있음 | — |
| 3 | Property role (속성 역할) | lit이 뜻을 아는 칸: 이름 · 날짜 · 시작 · 끝 · 달성 · 고정 일정 | 기본 DB에만 숨어 있음 | **어느 DB에나 역할을 붙이게** |
| 4 | Relation (연결) | 항목 → 다른 DB 항목 | 할 일→목표만 동작 | **아무 DB끼리나** |
| 5 | **Formula (계산 속성)** | `끝 − 시작`, `소요 − 예상`, 연결된 것 중 끝낸 비율 | 없음 (진행률은 lit 전용 코드) | **새로.** 상황 2·3·5의 열쇠 |
| **Input (입력)** |||||
| 6 | Checklist (체크 목록) | 달성 단계 바꾸기, 추가·삭제·끌어 옮기기·미루기 | 있음 | 어느 목록에서든 같게 |
| 7 | **Timestamp (타임스탬프)** | 누르면 지금 시각을 고른 칸에 | 있음: Timestamp · Start/Stop · Stopwatch · Timer · Time grid 칠하기 | 쓸 DB와 칸을 고르게 |
| 8 | Form · Rating · Counter · Daily check (입력 양식 · 점수 · 카운터 · 오늘 체크) | 칸 채우기 | 있음 | — |
| **View (보기)** |||||
| 9 | List · Table · Gallery · Calendar · Timeline · Time grid · Bar chart · Metric · Breakdown · Unlock cards | 보기 모양 | 있음 | — |
| 10 | **Filter (필터)** | 보고 싶은 것만, 정렬·묶기 포함. 보는 화면에서 바로 켬/끔 | 설정 안에만 | **화면 위 필터 칩** (상황 4) |
| 11 | **Conditional style (조건부 모양)** | 조건이 맞으면 회색·흐리게·숨김·색·아이콘. **미리보기로 고른다** | 없음 (긴축모드·희망사항 회색이 lit 전용) | **새로** (상황 3) |
| 12 | Aggregate (집계) | Count · Sum · Average · Max · Min · Streak · Days logged · Latest × 기간 | 있음 | 연결을 따라 집계 |
| **Automation (자동화)** |||||
| 13 | Signal (상황) | 이름 붙인 조건 | 10종 고정 | **사용자가 Formula·Aggregate로 직접 만드는 상황** |
| 14 | Rule (규칙) | Trigger → Action. Trigger: 항목이 생김/바뀜 · 항목마다 상황 · 상황 · 시각 · 하루 시작 · 기상 / Action: Create · Update · Update matching · Notify · Open · Effect | 있음 | 아래 15·16 |
| 15 | **Open form (기록지 열기)** | 규칙이 입력 양식을 띄우고, 저장하면 한 줄 | 없음 (Open은 영수증만) | 상황 1 |
| 16 | **Overlap check (충돌 확인)** | 시간이 겹치는 항목 찾기 | 없음 | 상황 5 |
| 17 | Effect (움직임) | Sparkle · Bounce · Shake · Float · Pulse · Spin · Pop · Glow · Confetti · Celebrate | 있음 | — |
| **Screen (화면)** |||||
| 18 | Widget (위젯) · Page (페이지) | 부품을 담는 그릇과 그걸 놓는 탭 | 있음 | 주간·월·목표·분석 고정 화면 → 위젯으로 |
| 19 | **Go to (이동)** | 누르면 다른 페이지·위젯으로, **누른 항목을 들고** | 없음 | 루틴 → 운동 탭 |
| 20 | Design (디자인) | 비개발자: 색·글꼴·모서리·밀도 / 개발자: HTML·CSS·JS | 있음 | — |
| 21 | Template (템플릿) | DB + 위젯 + 규칙 + 배치 묶음 | 일부 (페이지 틀, 위젯 꾸러미) | 마켓 단계 |

**새로 만들 것 7개:** Property role(어느 DB에나) · Relation(아무 DB끼리) · Formula · Filter 칩 · Conditional style · 사용자 Signal · Open form · Go to (+ 나중에 Overlap check).

## E. 템플릿: 문법으로 조립하는 법 (전부 (예))

### E-1. 목표 달성 · 포기 (상황 1)
| 재료 | 조립 |
|---|---|
| DB | 하루 일과(기본), 목표(기본), (예) "회고" 사용자 DB: 목표(연결) · 소감 · 실제 시간 · 임팩트 |
| 연결·계산 | 하루 일과 → 목표 연결, 목표.진행률 = 연결된 일과 중 끝낸 비율 (#4·#12) |
| 규칙 | 목표.상태가 "이룸"이 되면 → 축하 움직임 + (예) 알림 "{이름} 해냈어요" + **기록지 열기**(회고) (#15) |
| | 목표.상태가 "포기"가 되면 → (예) 알림 "여기까지 온 것도 기록이에요" + 기록지 열기 |
| 보기 | 목표 위젯: 진행률 게이지 + 상태 바꾸는 버튼 |

지금의 "이뤘어요 → 성취 기록지", ROI, "다음엔 누가"는 이 템플릿의 (예)로 옮긴다.

### E-2. 에너지 신호등 + 가용 시간 (상황 2)
| 재료 | 조립 |
|---|---|
| DB | (예) "에너지": 점수 · 시각 · 이유 |
| 입력 | 점수 부품 (시각은 timestamp가 자동으로) |
| 보기 | 신호등 모양 (색 구간은 사용자가) |
| 계산 | (예) 가용 시간 = 오늘 깨어 있는 시간 − 고정 일정 합 − (예)식사·이동 × (예) 에너지 계수 (#4) |
| 보기 | 숫자 게이지 "오늘 쓸 수 있는 시간"과 계산 과정 |

### E-3. 못 할 일정은 희망사항으로, 회색으로 (상황 3)
| 재료 | 조립 |
|---|---|
| 상황 | (예) "오늘은 무리": 계획한 시간 합 > 가용 시간 (#13) |
| 규칙 | 상황이 되면 → (예) 분류가 "필수"가 아닌 일과를 "희망사항"으로 (#14) |
| 조건부 모양 | 분류 = 희망사항이면 → **미리보기 중 고른 모양** (회색 / 흐리게 / 접기 / 아래로) (#11) |

지금의 "에너지 긴축모드"와 "희망사항 회색"은 이 템플릿으로 옮긴다.

### E-4. 소요 시간과 충돌 알림 (상황 4·5)
| 재료 | 조립 |
|---|---|
| 입력 | 일과 줄 옆 timestamp ▶/■ → 그 일과의 실제 시작·끝 (#6) |
| 계산 | 소요 = 실제 끝 − 실제 시작, 차이 = 소요 − 예상 (#4) |
| 보기 | 일과 줄에 소요·차이 칸, 10분 타임테이블이 칠함 |
| 규칙 | 항목이 생기거나 시간이 바뀌면 → 충돌 확인 (#16) → 겹치면 알림 + 흔들기 |

### E-5. 루틴 트래커 (지금 요청 2)
| 재료 | 조립 |
|---|---|
| DB | (예) "루틴" 사용자 DB: 이름 · 요일 · 예상 · 목표(연결) · 이동할 곳 |
| 규칙 | 하루 시작 → 오늘 요일의 루틴마다 하루 일과 만들기 (루틴 연결 포함) |
| 보기 | 트래커 = 하루 일과를 루틴 연결로 묶은 달력 / 격자, 달성이면 칠함 |

저장은 하루 일과에 한 번뿐이다. 트래커는 보기다. "루틴에서 옴" 칸은 연결 속성으로 바뀐다.

### E-6. 운동 (지금 요청 3)
| 재료 | 조립 |
|---|---|
| DB | (예) "운동 종목": 이름 · 부위 · 기구 / (예) "세트": 종목(연결) · 하루 일과(연결) · 무게 · 횟수 · RPE |
| 입력 | 세트 입력 칸 묶음, 세트 끝 timestamp → (예) 휴식 타이머 90초 |
| 계산 | (예) 지난번 무게 = 같은 종목의 마지막 값, (예) 추정 1RM |
| 이동 | 루틴 "운동" 줄을 누르면 → 운동 탭, 그 하루 일과를 들고 (#19) |
| 규칙 | 운동 끝 → 들고 온 하루 일과를 "달성"으로 → 루틴 트래커와 목표 진행률이 저절로 바뀜 |

## I. 화면 말을 사용자가 고칠 수 있나 (점검 2026-11-16)

| 화면 말 | 고칠 수 있나 | 어디서 |
|---|---|---|
| 탭 이름 | ✔ | 탭 두 번 누르기 |
| 위젯 제목 | ✔ | 위젯 제목 두 번 누르기 |
| 사용자 DB 이름 · 속성 이름 · 선택지 | ✔ | 위젯 에디터 → 저장 칸 |
| 부품 문구 (시작·끝 버튼 이름, 라벨) | ✔ | 위젯 에디터 → 화면 |
| 규칙의 알림 문구 | ✔ | 위젯 에디터 → 동작 |
| 내장 위젯의 버튼·칸 문구 | △ 일부 위젯만 (focus · tasks · routine · sleep · review · table · energy · pagebox · mission) | 위젯 설정 → 버튼·칸 문구 |
| **기본 DB 이름** (할 일 · 목표) | ✘ 코드에 고정 | `systemdb.ts` `systemTypes` |
| **기본 DB 속성 이름** (제목 · 상태 · 분류 · 날짜 · 시작 · 끝 · 예상 …) | ✘ 에디터에서 "기본"으로 잠김 | `Studio.tsx` 저장 칸 |
| **기본 DB 선택지** (할 일/한 일/일부/못 함/미룸/취소, 필수/희망사항/여가, 형광펜 색, 목표 기간·상태) | ✘ 코드에 고정 | `systemdb.ts` `STATE` `CAT` `HL` `HORIZON` `GSTATUS` |
| 상황 문장 ("오늘 순집중 8시간 이상") | ✘ | `signals.ts` `signalText` |
| 고정 화면 탭 안의 말 (주간 · 월 · 목표 · 분석), 목표의 "이뤘어요 / 포기", 성취·조정 기록지 | ✘ | 각 화면 코드 |

**결론:** 사용자가 직접 만든 것은 다 고칠 수 있다. **처음부터 깔려 오는 것(기본 DB, 내장 위젯, 고정 화면)은 대부분 못 고친다.** 결정 3·4·5가 모두 같은 한 가지 작업을 요구한다:

> **기본 DB를 사용자 DB처럼 만들기.** DB 이름 · 속성 이름 · 선택지를 사용자 것으로 저장하고, lit은 속성 역할(이름·날짜·시작·끝·달성·고정)과 달성 단계의 뜻(끝냄/안 끝냄/세지 않음)만 들고 있는다.

고정 화면과 내장 위젯은 H의 4·5단계(템플릿으로 옮기기)에서 함께 해결된다.
