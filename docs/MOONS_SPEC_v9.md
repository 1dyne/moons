# MOONS 명세 v9 — 기록 중심 개편 (2026-11-02)

> 대상: 구현하는 에이전트(Claude Code)와 개발자.
> 기준: `1dyne/moons` `main`(v8.1). 다인이 쓴 v9 초안을 코드와 대조해 다시 정리했다.
> v9는 **프런트 개편**이다. v6~v8의 분석(구조화 v3·비교·개념·앎의 상태), 학습 흐름, Satellite·MCP·OAuth, 팀, 내보내기는 로직을 바꾸지 않고 자리만 옮긴다.
> 시제품: [MOONS 내 달](https://claude.ai/artifact/JTFAqRiwswr6GxomojDttt) (학습 공간). 달은 완성형 예시이고, 형성 과정은 6.3을 따른다.

---

## 0. 작업 규칙

1. v7 0장 규칙을 이어간다. 내부 이름(`entries`, `planets` …)과 API 경로는 유지하고, 데이터 변경은 필드·테이블 추가로만 한다.
2. **화면 말은 단어로 쓴다.** 버튼·탭·메뉴는 한 단어(많아야 두 단어)다. 예: `정리 방식 고르기` → `정리`, `행성에 등록` → `등록`, `해결 기록 붙이기` → `해결 추가`. 문장형 버튼을 만들지 않는다.
3. **아이콘으로 충분한 동작은 아이콘만 둔다.** 녹음, 파일, 링크, 보내기는 아이콘 버튼 + `aria-label`.
4. 설명 문구 금지(v7 0.7)는 유지한다. 대신 미리보기와 예시로 보여준다.
5. 배경색·이미지 세부는 실제 제품 화면에서 정한다. 시제품의 색은 기준이 아니다. 브랜드 요소(MOONS 달 캐릭터, 아치 로고, 손그림 말풍선)는 그대로 쓴다.
6. 단계마다 커밋을 나누고 `docs/reports/v9-S{n}.md`에 보고서를 남긴다.

## 1. 목적과 확정 결정

v9는 사용자가 분류를 고민하지 않고 바로 쓰게 하고, 쌓인 기록이 곧 '내 달'과 분석이 되게 만든다. 리트 공부에 직접 써보니 매체 분류(스파크·자료), 입력 전 형식 선택, 등록 후 재정리가 생각을 틀에 맞추게 했다.

| # | 결정 |
|---|---|
| 1 | 주요 공간은 **기록 · 학습 · Space · 공유 · 마켓** 다섯 개. 기본 공간은 기록 |
| 2 | 입력 전에 형식을 고르지 않는다. 빈 페이지에 바로 쓰고, 형식은 도구줄에서 그 자리에 **넣는다**(PPT 삽입 방식) |
| 3 | 스파크·덤프·자료 구분은 사용자가 고르지 않는다. 입력 행동으로 정해진다(4.4) |
| 4 | 자주 쓰는 형식은 즐겨찾기. 기본 형식을 고쳐 **내 구조**로 여러 개 등록한다 |
| 5 | **창고** = 가공 없이 넣어둔 파일·링크(폴더 있음). **모행성** = MOONS로 쓴 기록의 분류(상하 계층 있음) |
| 6 | 학습 공간은 사용자의 달과 현황을 보여주는 대시보드. 달과 그래프는 실제 데이터로만 그린다 |
| 7 | **왜소행성 = 모행성이 없는 페이지.** 개념의 "내 말로 설명한 적 없음"은 **설명 전**이라고 부른다(2장) |
| 8 | 확신은 개념과 페이지마다 **별 5개(반 개 단위 = 1~10점)**로 매긴다 |
| 9 | MOONS 추천(형식·모행성·연결)은 설정에서 켠 사람에게만, 떠 있는 달이 제안한다 |
| 10 | 임포스터는 **MOONS로 비춰본 결과 안에서만** 나온다. 사용자의 페이지 원문에는 섞지 않는다 |
| 11 | 첫 화면의 큰 캐릭터는 없앤다. 헤더 로고 자리를 **MOONS 달 캐릭터**로 바꾼다. 아치 로고 + 말풍선 인사는 **처음 들어올 때만** 보인다 |
| 12 | 커넥터(MCP)는 읽기·제안·Satellite 등록까지만 맡는다. 더 큰 작업은 Satellite로 확장한다 |

**유지할 원칙**
- 분석에 쓰는 원문은 바꾸지 않는다(스냅샷, 10.1).
- 내 말 · 자료 · AI 층을 섞지 않는다.
- '설명 가능'은 사용자가 직접 쓴 문장만 근거로 한다.
- AI가 제안한 지식은 승인 전까지 사용자 지식이 아니다.
- 판정할 수 없는 내 생각·입장은 채점하지 않는다.

## 2. 용어

| 화면 말 | 뜻 | 코드 |
|---|---|---|
| 페이지 | 기록 공간에서 쓰는 문서. 자유롭게 고친다 | **신규** `pages` (10.3) |
| 블록 | 페이지 안의 한 칸(줄글, 제목, 표, 카드 …) | `Page.blocks` |
| 스냅샷 | 분석용으로 잠근 페이지의 한 시점 | 기존 `Entry` (`locked:true`) |
| 모행성 | 페이지 분류. 상하 계층, 여러 개 가능 | `planets` + **신규** `Planet.parentId` |
| 왜소행성 | 모행성이 없는 페이지 | `planetIds.length===0` |
| 창고 | 가공 없이 넣어둔 파일·링크, 폴더 | **신규** `assets`, `folders` |
| 내 구조 | 사용자가 등록한 블록·페이지·보기 형식 | **신규** `structures` (기존 `forms` 확장) |
| 개념 | 기록을 가로질러 쌓이는 명사구 단위의 앎 | `concepts` |
| 설명 전 | 개념을 내 말로 설명한 적 없음 | `unfamiliar(c)` (화면 이름만 바꿈) |
| 단계 | 개념·페이지의 앎의 상태: 들어옴 · 정리됨 · 확인됨 · 설명 가능 | `Knowledge` |
| 확신 | 내가 느끼는 확신, 별 5개(1~10) | `confidence` (기존 플래너 타입 재사용) |
| 내 달 | 개념 데이터로 그린 3D 달(학습 공간) | 파생 |
| 단면도 | 한 분야를 잘라 단계와 확신을 보여주는 그래프 | 파생 |

**용어 정리 작업(S1에 포함):** 지금 코드는 두 뜻을 섞어 쓴다. 모행성 없는 노트는 '주제 없음'(`i18n-ko.ts` `'Dwarf Planet'`), 설명 안 한 개념은 '왜소행성'(`'Dwarf planets'`, `DwarfBadge`). v9에서는 앞의 것을 **왜소행성**, 뒤의 것을 **설명 전**으로 바꾼다. 내부 이름(`unfamiliar`)은 유지한다.

## 3. 정보 구조

웹은 왼쪽 **아이콘 레일**로 공간을 바꾸고, 그 옆 패널에 공간별 내용을 둔다. 앱(모바일 폭)은 같은 공간을 아래 탭으로 옮긴다. 지금의 햄버거 메뉴와 상단 탭 묶음(v7 4장)은 레일로 대체한다.

| 레일 | 역할 | 흡수하는 기존 화면 | 보이는 때 |
|---|---|---|---|
| 기록 | 쓰기, 최근 페이지, 창고 | 기록(Capture), 노트 목록, 자료, 폼 배너 | 항상, 기본 |
| 학습 | 내 달, 현황, 비교, 질문, 대화 목록 | 스테이션, 비교 작업대, 대화 탭, 노트의 구조도·비교 | 항상 |
| Space | 내가 구성하는 전체 보기 | 내 우주, 개념 목록·개념 페이지, 저장된 보기, 보드 | 항상 |
| 공유 | 같은 자료를 두고 이해 비교 | 팀 | 팀에 초대받았거나 만든 사람 |
| 마켓 | 내 구조 공유·판매 | 신규 | 출시 때 |
| ─ (구분선) | 고정한 Satellite | 플래너, LEET drill, Dock … | 사용자가 고정한 것 |

- **헤더 로고 자리**: MOONS 달 캐릭터(`MoonCharacter`, 눈이 커서를 따라감). 누르면 기록 공간.
- **프로필 메뉴**: 계정, 설정, 내 구조 관리, Satellite 목록(설치·제거), 공유 공간 만들기.
- **떠 있는 달 버튼**: 그대로 유지. 누르면 MOONS 대화(지금 보는 페이지·개념이 맥락으로 붙음). MOONS 추천이 켜져 있고 제안이 있으면 달 옆에 말풍선(8장).
- **맥락 유지**: 공간을 바꿔도 보던 대상을 이어간다. 기록에서 페이지를 보다 학습으로 가면 그 페이지의 구조·비교가 열리고, Space로 가면 그 페이지의 위치로 확대된다.
- **v7 탭과의 대응**: 노트 화면의 `원문`은 기록(페이지), `구조도 · 비교 · 다음 탐색`은 학습의 오른쪽 패널, 개념 페이지는 어디서 눌러도 오른쪽 패널로 열리고 `전체 보기`를 누르면 Space의 개념 보기로 간다.

## 4. 기록 공간

사용자는 화면을 열면 고르지 않고 바로 쓴다. 등록·정리 단계는 없다.

### 4.1 첫 화면
- 가운데: 빈 페이지와 제목 자리. 커서가 바로 놓이고, 치면 줄글이 된다.
- 위: 즐겨찾기 도구줄 + `더보기`.
- 왼쪽: 최근 페이지(최근 순, 모행성으로 거르기) + `새 페이지`.
- 처음 들어올 때(세션 첫 진입): 빈 페이지 위에 아치 로고 + 손그림 말풍선 인사(v8 `Logo`·`Speech` 재사용). 첫 글자를 치면 접힌다.
- 쓰기 시작 후: 최근 페이지는 접히고 페이지가 넓어진다.
- 모바일: 도구줄은 키보드 위, 최근 페이지는 밀어서 연다.

### 4.2 편집
- 위치를 골라 도구를 누르면 그 자리에 블록이 들어간다. 현재 줄을 제목으로 바꿀 수 있다.
- 글자를 고르면 `하이라이트` `굵게` `링크` 메뉴.
- 블록은 끌어서 순서를 바꾼다. 캔버스 블록 안에서는 핀보드처럼 자유 배치.
- 완성한 뒤에도 블록을 더하고 옮길 수 있다.
- 입력칸의 녹음 · 파일 · 링크는 아이콘만 둔다(0.3).

### 4.3 기본 블록
새 블록을 더해도 페이지 모델이 바뀌지 않아야 한다(`Block.kind` + `value`).

| 블록 | 동작 | 단계 |
|---|---|---|
| 제목, 줄글 | 기본 문서 | 1차 |
| 채팅 | MOONS에게 덤프하는 칸. 내 입력은 `user`, MOONS 답은 `ai` | 1차 |
| 표 | 열 이름을 치면 열이 됨 | 1차 |
| 이미지, 파일, 링크, 녹음 | 첨부·끌어다 놓기 | 1차 |
| 캔버스 | 핀보드형 자유 배치 | 1차 |
| 카드, 빈칸 카드 | 복습 동작이 있는 항목(앞·뒤) | 2차 |
| 질문 카드 | 한 장씩 넘기며 답함 | 2차 |
| 오답 노트 | 상황 · 오류 · 이유 · 해결 칸 + 기출 문항 + 상태(미해결/해결 중/해결됨) + `해결 추가` | 기본 내 구조 |
| 비교표, 코넬 노트 | 칸 조합 | 기본 내 구조 |
| 타임라인, 순서도, 체크리스트, 갤러리 | 전용 보기 | 3차 |

- 채팅 블록에서 덤프할 때 **채팅용 틀**(질문 순서가 있는 덤프 틀, 예: 문항 → 상황 → 이유)을 놓고 쓸 수 있다. 틀은 내 구조의 한 종류(`level:'block'`, `kind:'chat'`)다.
- 오답 노트의 `해결 추가`는 같은 페이지 아래에 날짜가 붙은 해결 기록을 쌓는다. 상태는 사용자가 바꾼다.

### 4.4 입력 행동과 출처 층
사용자는 종류를 고르지 않는다. 블록의 `by`는 이렇게 정해지고, 블록 옆 표시를 눌러 바꿀 수 있다.

| 행동 | `by` | 분석에서 |
|---|---|---|
| 직접 친 글, 채팅 블록의 내 입력 | `user` | 내 말(기존 `dump` 문장) |
| 붙여넣은 긴 글, 파일, 링크 본문, 녹음 원본 | `source` | 자료(기존 `media`) |
| MOONS 답, AI가 채운 칸 | `ai` | AI 층, 승인 전 사용자 지식 아님 |

스냅샷(10.1)을 만들 때 `user` 블록은 `kind:'dump'` Entry의 문장으로, `source` 블록은 `kind:'media'` Entry로 들어간다. 기존 분석 코드는 그대로 돈다.

### 4.5 내 구조
- **내 블록**: 기본 블록을 고친 형식(예: 칸을 바꾼 내 코넬, 채팅용 틀). 현재 페이지에 끼워 넣는다.
- **내 페이지**: 여러 블록과 배치를 묶은 형식(예: 리트 오답). 새 페이지로 연다.
- **내 보기**: Space의 보기 형식(7.1).
- 등록은 쓰던 화면에서 `구조 저장`. 내용은 빼고 블록·배치·칸 이름·달의 질문만 남긴다.
- 개수 제한 없음. 모행성과 자동 연결하지 않는다.
- 기존 `forms`(블록 11종, 사진 → 폼)는 내 구조로 옮긴다. 종이 사진 → 구조 초안 기능은 유지한다.
- 마켓에 올릴 수 있도록 사용자 데이터와 분리해 저장한다.

### 4.6 온보딩
처음 가입한 사람에게 한 번만 나온다. 건너뛸 수 있다.
1. **무엇을 기록하나요** — 칩 여러 개 선택: 공부 · 시험 · 일 · 프로젝트 · 독서 · 일상 …(선택 결과로 첫 모행성 후보를 만든다. 사용자가 이름을 고친다.)
2. **자주 쓸 형식** — 기본 블록과 기본 내 구조를 **미리보기 타일**로 보여준다(예: 오답 노트, 뒤집는 카드, 코넬, 표). 고른 것이 즐겨찾기 도구줄에 올라간다. 고르지 않아도 줄글·제목·채팅·표·첨부는 기본으로 있다.
3. **MOONS 추천** — 켜기/끄기(8장). 기본값은 켜기.
4. 끝나면 빈 페이지로 들어간다. 아치 로고 + 말풍선 인사가 처음으로 보인다.

도구줄은 쓰면서 언제든 바꾼다(`더보기` → 끌어서 올리기·내리기).

### 4.7 창고
- 기록 공간 안의 보관함. 폴더를 만들고, 파일·폴더를 끌어다 놓아 올린다. 웹 링크도 같은 방식.
- 창고에만 넣으면 구조화하지 않는다. AI 비용 0.
- 파일을 고르고 `정리`를 누르면 새 페이지가 열리고 파일이 `source` 블록으로 들어간다. **원본 파일은 창고에 그대로 남고**, 페이지는 `원본` 링크로 이어진다.
- 비교의 원본으로 고를 수 있다(지금은 Material만 원본이 될 수 있다).

### 4.8 모행성
- **상하 계층**: `Planet.parentId`. 하위 모행성을 고르면 상위는 자동 포함(저장은 고른 것만, 상위는 계산). 고르는 창은 트리.
- 상위 모행성의 색 계열 안에서 하위가 명도·채도로 나뉜다. 사용자가 컬러칩으로 직접 바꾸면 그 색이 우선.
- 달이 제안한 모행성을 누르거나(8장), 페이지를 모행성으로 끌어다 놓는다(앱은 길게 눌러 선택). 끌기는 이동이 아니라 추가.
- 모행성이 없어도 저장된다 → 왜소행성.
- 상위 모행성을 지우면 하위는 한 단계 위로 올라간다. 페이지의 소속은 남는다.

## 5. 학습 공간

최근 기록이 모여 만든 내 달과 실제 분석을 보여주고, 그 결과에서 다음 공부로 들어가는 곳.

### 5.1 화면 순서
1. **요약**: 분야(모행성 칩), 분야별 이해도, 확인할 곳.
2. **내 달**: 앞면은 근거가 있는 지식, 뒷면은 아직 점검 전.
3. **단면도**: 선택한 분야의 단계와 확신.
4. **학습 도구**: 이어가던 질문, 비교, 개념 설명, 복습, 대화 목록.

오른쪽 패널(데스크톱) / 아래 시트(모바일)는 선택한 개념·페이지의 상세: 실제 단계, 확신(별), 쌓인 기록, 근거, 다음 질문, `노트` `비교` `설명`.

### 5.2 요약
- **분야**: 최상위 모행성. 누르면 달과 단면도가 그 분야로 바뀐다. 하위 모행성은 칩 아래 줄로.
- **이해도**: 분야별로만 보여준다(전체 한 수치 없음). 근거 개념 수를 함께 쓴다. 예: `72 · 근거 9개`.
- **확인할 곳**: 6.4 순서로 최대 3개. 각 항목은 개념과 근거 노트로 바로 간다.
- 화면에 `내 기록 기준`을 표시한다.

### 5.3 상태
| 상태 | 달 | 요약·단면도 | 조건 |
|---|---|---|---|
| 비어 있음 | 작은 씨앗 | 숨김 | 기록 없음 |
| 형성 중 | 기록마다 실제 개념 단어가 올라가 표면이 쌓임 | `형성 중`과 진행 수치만 | 기준 미달 |
| 공개 | 기준을 넘은 분야의 지형 확정, 나머지 분야는 형성 중 표면 | 기준을 넘은 분야만 공개 | 분야 하나 이상 기준 충족 |

기준 초기값: 분야별 개념 6개, 그중 근거 개념 3개. 설정 상수(`KNOWLEDGE_REVEAL`)로 두고 실사용 뒤 조정한다.

### 5.4 내 달
- 단어는 근거 노트가 있는 실제 개념이다. 예시 단어를 채우지 않는다.
- 새 개념이 생기면 단어가 올라가 자리를 잡고, 상태가 바뀌면 지형이 바뀐다.
- 같은 데이터는 항상 같은 모양(6.6).
- `뒷면` 버튼을 항상 둔다. 달을 돌리지 않아도 점검 전 목록으로 간다.
- 지형·단어를 누르면 오른쪽 패널에 개념·근거·다음 질문.
- WebGL이 없으면 달 대신 목록, 단면도는 그대로.

### 5.5 단면도
- 점 하나가 개념 하나. 기본 분야는 최근 가장 많이 다룬 모행성.
- 땅 높이 = 단계, 점선 = 확신, 아래층 = 쌓인 기록, 수면 아래 = 설명 전. 확신 기록이 없는 구간은 점선을 끊는다.
- 크레이터·별 표시는 6.2.

### 5.6 학습 흐름
- 비교, 질문 노트(스테이션), 다음 탐색, 개념 설명, 대화는 학습 공간에서 연다. 로직은 v7·v8 그대로.
- 비교 작업대는 `자료 | 내 기록 | 달` 3단.
- 내 말로 설명하면 개념 상태가 바뀌고 달과 단면도가 다시 그려진다.
- 필수 과제와 밀린 숫자는 두지 않는다.

## 6. Knowledge 분석 규칙

달과 단면도는 같은 개념 데이터를 두 방식으로 그린 것이다. 모든 지형과 점은 근거 노트까지 추적된다.

### 6.1 단위와 값
- 계산 단위는 **개념**. 여러 분야에 속하면 각 분야에 모두 표시.
- **단계 점수** `s_c`: 들어옴 25 · 정리됨 50 · 확인됨 75 · 설명 가능 100 (v7 앎의 상태 그대로, 4단계).
- **설명 전**(`unfamiliar`): 단계와 별개인 표시. 단계 점수는 그대로 두고 단면도 수면 아래에 놓는다.
- **근거**: 비교 결과(Kept/Shifted/Missed가 있는 대조), 풀이 기록(Satellite `attempt`), 내 설명(설명하는 `user` 문장). 하나라도 있으면 **근거 개념**.
- **확신** `k_c`: 별점 1~10 → `k_c × 10`(10~100). 개념에 직접 매긴 값이 우선. 없으면 그 개념이 나온 페이지들에 매긴 별점의 평균을 쓰고 `페이지 기준`으로 표시한다. 둘 다 없으면 없음(점선 끊김). 말투에서 추정한 값(`GNode.hesitant` 등)은 `추정`으로 따로 표시하고 계산에 넣지 않는다.

### 6.2 시각 요소
| 요소 | 데이터 | 규칙 |
|---|---|---|
| 달 앞면 | 근거 개념 | 근거가 생기면 뒷면 → 앞면 |
| 달 뒷면 | 근거 없는 개념, 구조화·비교 전 페이지 | 근거가 생기면 앞면으로 |
| 고지 높이 / 단면 땅 높이 | 단계 점수 | 같은 값 |
| 고지 범위 / 단면 아래층 | 개념이 나온 기록 수 | 많을수록 넓고 두껍게 |
| 단면 수면 아래 | 설명 전 | 내 말로 설명하면 수면 위로 |
| 단면 점선 | 확신 `k_c` | 없으면 끊음 |
| 크레이터 | 확신이 실제보다 높음 | `k_c − s_c ≥ 50` |
| 별 표시 | 생각보다 아는 개념 | `s_c − k_c ≥ 25` |
| 안개 | 근거 없는 영역 | 근거가 채워지면 걷힘 |

### 6.3 이해도
근거 개념만 쓴다. 개념별 기록 수로 가중 평균한다. 점검 전 개념은 뺀다.

```latex
U_f = \frac{\sum_{c \in f} n_c s_c}{\sum_{c \in f} n_c}
```
`U_f` 분야 이해도, `n_c` 개념 c가 나온 기록 수, `s_c` 단계 점수. 화면에는 이해도와 근거 개념 수를 함께 쓴다.

### 6.4 확인할 곳 순서
1. 확신과 실제가 어긋난 개념(크레이터, 그다음 별)
2. 기록이 많은데 설명 전인 개념
3. 기록이 많은데 단계가 낮은 개념
4. 뒷면의 점검 전 페이지

한 번에 최대 3개. 확인하지 않아도 밀린 숫자로 쌓지 않는다.

### 6.5 단면 순서
- 지금 개념 관계(`ConceptRel`)에는 선행 관계가 없다. 1차: `part_of`·`kind_of` 묶음끼리 모으고, 묶음 안에서는 기록 수가 많은 순.
- 선행 관계는 후속 범위(`ConceptRel`에 `prerequisite` 추가). 배치 이유가 없는 인과를 화면에서 말하지 않는다.

### 6.6 달 좌표
- 분야별 영역을 정하고, 개념 위치는 개념 ID의 해시로 결정한다. 다시 열어도 같은 자리.
- 같은 묶음은 가까이, 단어가 겹치면 확대할 때만 보인다.

### 6.7 판정하지 않는 것
- 내 생각·입장·가치 판단은 이해도에 넣지 않는다(기존 `DumpLayer` 평가는 숨김 유지). 달의 별도 영역에 주제와 빈도만.
- 근거 없는 개념은 앎의 높이로 추정하지 않는다.
- 상태가 뒤로 가면 지형도 낮아진다.

## 7. Space, 공유, 마켓

### 7.1 Space
사용자가 자기 구조로 들어가 지내는 전체 화면. 보기를 여러 개 만든다.

- **보기 종류**: 우주(그래프) · 보드 · 표 · 갤러리 · 타임라인. 필터와 함께 저장한다. 기존 `views`(우주 전용)를 일반 보기 구조로 넓힌다.
- **우주 보기** (옵시디언 그래프처럼 평평하게, 별·광택·3D 없음):
  - 모행성은 원, 크기는 쌓인 기록 수에 비례. 모행성끼리는 공유 페이지 수만큼 굵은 선.
  - 확대 단계: 기본은 모행성만 → 조금 확대하면 하위 모행성과 페이지가 **점** → 더 확대하면 점이 **카드**로 펼쳐지고 개념 카드(눌러서 뒤집기)와 Satellite 바로가기가 보인다.
  - 모행성 근처로 확대하면 `들어가기`. 들어가면 그 모행성의 상세(하위 모행성 칩, 저장된 보기 칩, 페이지 사이 이름 붙은 선)만 남는다.
  - 마우스를 올리면 연결된 것만 밝고 나머지는 흐려진다.
  - 색·크기 기준: 분야 / 앎의 상태 / 최근.
  - 바탕 톤은 실제 화면에서 정한다(후보: 우주에 들어가면 헤더·패널까지 어두운 톤으로 바뀌는 방식).
- **보드 보기**: 핀보드·무드보드. 페이지·개념·창고 파일·이미지·포스트잇을 끌어와 놓고 실로 잇는다. 보드는 원본을 복사하지 않고 가리킨다.
  - 선에는 이름(상황·이유·반례 …)과 범위가 있다: `전체`(기본, Space 전체 연결) / `이 보드`(이 보드에서만).
- **구역**: 한 보기 안에 작은 우주, 오답 표, 감정 패턴, Satellite 바로가기를 함께 놓는다.
- **사용자 DB 열**: 표 머리에 이름을 치면 열이 되고, 속성 종류는 값에서 알아차린다. 종이 표·기존 표를 넣으면 같은 열을 제안한다. 폼 칸 값은 열이 될 수 있다. AI가 채운 값은 AI 표시.
- 학습의 내 달·단면도도 Space 보기로 추가할 수 있다.
- 개념 목록·개념 페이지(v7 4.3)는 Space의 `개념` 보기로 들어온다.

### 7.2 공유
팀 공간(v6 9.2) 그대로. 같은 자료를 두고 각자 이해를 비교한다. 개인 달은 자동 공유하지 않는다.

### 7.3 마켓
출시 전에는 레일에 보이지 않는다. 판매 단위는 내 블록 · 내 페이지 · 내 보기. 사용자 노트와 개인 데이터는 포함하지 않는다. 수수료·정책은 S9 전까지 설계하지 않는다.

## 8. MOONS 추천과 대화

- 설정 `MOONS 추천`(온보딩에서 고름, 기본 켜기). 끄면 아래 제안은 하나도 뜨지 않는다.
- 켜져 있고 제안이 있으면 **떠 있는 달 옆에 작은 말풍선**이 뜬다. 누르면 제안 카드, `적용` / `그냥 두기`.
- 제안 종류:
  - **형식**: 쓰는 글에 맞는 블록·내 구조(예: 문항 번호·원인·다음 시도가 보이면 오답 노트). 적용하면 사용자의 글을 그대로 칸에 옮긴다(글자를 바꾸지 않음).
  - **모행성**: 이 페이지를 붙일 모행성(기존 `tagProposal`).
  - **연결**: 다른 모행성의 비슷한 페이지(Space·보드에서는 그 자리에 달 스티커로도 표시).
- 제안은 쓰기를 막지 않는다. 같은 제안을 7일 안에 다시 띄우지 않는다(v5 알림 규칙).
- 사용자가 무시하거나 직접 고른 형식을 기억해 다음 추천에 반영하는 것은 **후속 범위**(지금 MOONS AI에는 사용자별 장기 메모리가 없다).
- 대화는 지금처럼 떠 있는 달에서 시작하고, 대화 목록·대화 노트는 학습 공간에 있다.

## 9. Satellite와 AI 연결

### 9.1 커넥터(MCP)
- 노트·개념 읽기, 정리안 제안, Satellite 등록(v8 4.2 그대로).
- 커넥터가 보낸 제안은 승인 후 반영. 승인은 묶음. 승인 대기는 있을 때만 한 줄로 보이고, 일상 기록에는 적용하지 않는다.
- 더 복잡한 작업은 도구를 늘리지 않고 Satellite로 만든다.

### 9.2 AI 비용과 달의 형성
- MOONS AI를 켠 사람: 스냅샷 후 개념 추출과 구조화를 예약 처리.
- MOONS AI를 끈 사람: 외부 AI의 정리안이나 Satellite 기록이 승인되면 달이 변한다.
- 둘 다 없는 기록은 뒷면으로 간다.
- 긴 자료의 정답 지도와 비교는 별도 단계. 비용은 기존 `ai_calls` 표로 측정.

### 9.3 MOONS 안에서 쓰는 Satellite
- 자주 쓰는 Satellite는 레일 구분선 아래에 고정. 누르면 MOONS 화면 안에서 전체로 열린다(지금의 iframe 방식, 막히면 새 탭).
- MOONS는 사용자 코드를 호스팅하지 않는다. 주소 등록 방식 유지.
- 생활 기록처럼 표준화된 앱은 **생활 데이터 허브**를 쓴다(9.4).
- 직접 만든 웹은 Satellite별 전용 저장소. 자기 데이터만 읽고 쓴다.
- MOONS 안에서 열린 앱은 `postMessage`로 저장을 요청한다. 등록된 URL의 origin과 일치할 때만 받는다. 브라우저 코드에 토큰을 넣지 않는다.
- 노트로 남길 내용은 지금처럼 들어온 것 함 승인을 거친다.
- `satellite_guide`에 이 방식을 추가해 웹을 만드는 AI가 처음부터 맞추게 한다.

### 9.4 플래너와 Dock
- **플래너**는 독립 Satellite 앱이다(`artifacts/planner`, 자기 주소, PWA). 기록은 생활 데이터 허브(`/life/v1`, `life_*`)에 쌓인다. 설계는 브랜치 `claude/moons-planner-builder-agent-embo97`의 `docs/PLANNER_SPEC_v1.md`, `docs/LIFE_DATA_CONTRACT_v0.md`. v9에서는 레일에 고정할 수 있는 Satellite로 보이고, 확신·작업 시간 데이터는 허락한 범위만 읽는다.
- **Dock**(`docs/MOONS_DOCK.md`)은 프로젝트 관리 장치다. 프로젝트별 목표·일정·검토함·맥락 노트, GitHub·Railway 등 연결, 확정한 지시서를 Claude Code/Codex에 넘기는 흐름. v9에서는 내장 Satellite로 Satellite 목록에 두고, 원하면 레일에 고정한다.
- **임포스터**: 내장 Satellite. 1장 결정 10의 범위로 줄인다(MOONS로 비춰본 구조·비교 결과 안에서만 나오고, 공개 규칙은 v6 8장 그대로).

## 10. 데이터와 코드

### 10.1 데이터 흐름
1. 사용자가 페이지에 블록을 쓴다. 자동 저장.
2. 정해진 시점에 페이지를 잠긴 `Entry` 스냅샷으로 만든다. `user` 블록 → `dump` 문장, `source` 블록 → `media` Entry.
3. 스냅샷에서 구조화·개념 추출·비교·앎의 상태 계산(기존 코드).
4. 개념별 `ConceptKnowledge`를 집계한다.
5. 같은 집계로 달·단면도·요약을 그린다. 지형은 저장하지 않고 파생한다.

**스냅샷 시점(기본값)**: 페이지를 나갈 때 변경분이 있으면 새 스냅샷(`parentEntryId`로 이전 스냅샷과 연결). 예약 구조화는 그날 마지막 스냅샷에만 실행. 개념 근거는 **최신 스냅샷**을 가리키고, 이전 스냅샷의 분석은 기록으로 남는다.

### 10.2 기존 코드 처리
| 영역 | 지금 | v9 |
|---|---|---|
| 내비게이션 | 햄버거 메뉴 + v7 탭 8개 | 아이콘 레일 + 맥락 유지 |
| 기록 입력 | 스파크·자료 탭, 폼 배너, 별도 녹음 버튼 | 빈 페이지 하나, 아이콘 첨부, 폼은 도구줄 |
| `Entry` | 저장 즉시 `locked:true` | 유지. 사용자가 고치는 건 `Page`, 분석은 스냅샷 |
| `forms` | 블록 11종, 사진 → 폼 | `structures`로 확장(블록·페이지·보기) |
| 동기화 | 항목 단위 업서트 + 이벤트 | 페이지는 별도 테이블. 편집 중 이벤트 없음, 스냅샷 때만 이벤트 |
| 노트 화면 | 원문·구조도·비교 한 화면 | 원문 = 기록의 페이지, 나머지 = 학습 패널 |
| Station, CompareDesk, 대화 탭 | 탭 | 학습 공간 |
| 내 우주 | 3D·성운 배경 | Space의 우주 보기(평평한 그래프), 3D는 후속 |
| 보기 | `UniverseView` 우주 전용 | 보기 일반 구조(우주·보드·표·갤러리·타임라인) |
| 개념 | `concepts`, 앎의 상태 | Knowledge 집계의 기준. 목록·페이지는 Space |
| 창고 | 자료는 문장 Entry, 폴더 없음 | `assets`, `folders` 신규. 파일은 object storage |
| 모행성 | 평면 목록 | `parentId` 추가 |
| 확신 | 플래너 `Confidence`(1~10, `targetType` concept/task/node/project) | 그대로 재사용, `targetType`에 `page` 추가, 별 5개 UI |
| Satellite | iframe, `POST /api/satellite-records` | 전용 저장소, `postMessage`, 레일 고정 |
| 플래너 | `main`에는 v6 내장 플래너, 브랜치에 독립 앱 + 허브 | 브랜치 병합 후 레일 Satellite로 연결 |

### 10.3 새 데이터 형태
```ts
type Page = {
  id: string; title?: string;
  blocks: Block[];
  planetIds: string[];          // 고른 모행성만 저장, 상위는 계산
  structureId?: string;         // 내 페이지로 만들었으면
  latestEntryId?: string;       // 최신 스냅샷
  assetId?: string;             // 창고 원본에서 시작했으면
  updatedAt: string; createdAt: string;
};
type Block = {
  id: string; kind: string;     // 'heading' | 'text' | 'chat' | 'table' | 'file' | 'canvas' | 'card' | ...
  by: 'user' | 'source' | 'ai';
  order: number;
  canvas?: {x: number; y: number; w: number; h: number};
  value: unknown;               // kind별 스키마로 검증
};
type Planet = /* 기존 */ {parentId?: string};
type Structure = {
  id: string; name: string;
  level: 'block' | 'page' | 'view';
  blocks: unknown[]; moonPrompts?: string[];
  source: 'builtin' | 'manual' | 'photo' | 'market';
  favorite?: boolean; position?: number;    // 도구줄
};
type Asset = {id: string; folderId: string | null; name: string; mime: string; size: number; url?: string; storageKey?: string; createdAt: string};
type Folder = {id: string; name: string; parentId: string | null};
type ConceptKnowledge = {       // 파생값, 저장하지 않음
  conceptId: string; field: string;      // 최상위 모행성
  stage: 1 | 2 | 3 | 4;                  // 들어옴~설명 가능
  unexplained: boolean;                  // 설명 전
  confidence: {value: number; by: 'concept' | 'page'} | null;   // 1~10
  recordCount: number;
  side: 'front' | 'back';
  terrain: 'highland' | 'crater' | 'fog' | 'sea';
  evidence: {entryId: string; sentences?: number[]; kind: 'compare' | 'attempt' | 'explain'}[];
};
```
필드 이름과 저장 위치는 구현 때 동기화 구조에 맞춰 조정한다.

### 10.4 먼저 확인할 코드
- 예약 구조화가 `v5/daily.ts`(`runDaily`)와 겹치지 않는지.
- 다른 도메인 iframe에서 로그인·저장이 동작하는지(실제 브라우저).
- 플래너 브랜치의 `components/Planner.tsx`, `lib/planner.ts` 변경과 v9 내비게이션 변경이 겹치는 곳.

## 11. 구현 순서

메뉴와 입력을 먼저 바꿔 피로를 줄이고, 그다음 Knowledge 데이터와 달을 연결한다.

| 단계 | 작업 | 완료 기준 |
|---|---|---|
| S1 | 레일, 맥락 유지 전환, 헤더 달 캐릭터, 용어 정리(2장), 단어형 화면 말 | 모든 기존 기능이 새 위치에서 열린다. 옛 경로는 리다이렉트 |
| S2 | 페이지 편집기 1차 블록 + 입력 통합 + 스냅샷 | 글·파일·녹음을 모드 선택 없이 저장, 스냅샷이 기존 분석을 통과 |
| S3 | 모행성 계층, 별점 확신, 온보딩, 즐겨찾기 도구줄 | 하위를 고르면 상위가 포함되고, 별점이 개념·페이지에 저장 |
| S4 | 예약 구조화, Knowledge 집계 | 같은 데이터에서 같은 값이 재현 |
| S5 | 학습 공간: 요약, 형성 중, 내 달, 단면도, 뒷면 | 모든 지형과 점이 근거 노트로 이동, 빈 데이터에 가짜 값 없음 |
| S6 | 창고와 폴더 | 구조화 없이 보관, `정리`로 페이지 시작 |
| S7 | 내 구조(블록·페이지·채팅 틀), MOONS 추천 | 쓰던 화면에서 등록해 다시 쓰기, 추천을 끄면 제안 0 |
| S8 | Space 보기(우주·보드·표), 사용자 DB 열 | 확대 단계·들어가기·보드 선 범위, 열을 만들고 보기를 저장 |
| S9 | Satellite 레일 고정, 전용 저장소, 플래너 연결 | 새로고침 후에도 MOONS 안에서 쓴 데이터 유지 |
| S10 | 공유 정리, 마켓 | 사용자 데이터 없이 구조를 공유 |

## 13. 남은 결정 (기본값으로 시작, 다르면 따른다)
- **개발 기준**: 이 브랜치(`main` 기준)에서 시작하고, 플래너 브랜치는 S9 전에 병합한다.
- **형성 기준**: 분야별 개념 6개 · 근거 개념 3개.
- **확신 보충**: 개념 별점이 없으면 페이지 별점 평균을 `페이지 기준`으로 쓴다.
- **MOONS AI 모델**: 개념 추출·구조화 모델은 비용 측정 후 정한다.
- **우주 보기 바탕 톤**: S8에서 실제 화면으로 비교해 정한다.
- **3D 탐방**: 후속 범위.
- **마켓 수수료·정책**: S10 전까지 설계하지 않는다.
