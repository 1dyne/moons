# v7 M4 보고서 — 덤프 받아 적기 · 대조 · 다음 탐색 · 앎의 상태

## 1. 바뀐 것
- **덤프 받아 적기 층** (6.2, `v5/dump-map.ts`): 스파크를 구조화하면 기존 "내가 이해한 지도"(사용자의 묶음·표기를 따르는 v2 지도)는 그대로 두고, 그 위에 받아 적기 층을 더함.
  - `moons_dump_claims`: 사용자가 이은 두 생각(글자 그대로), 사용자가 쓴 연결어(`asserted`, 예 "그래서", "->"), 같은 단어의 두 뜻(`term@뜻`), 비약(`gap`: A→C, 빠진 단계). 원문에 글자 그대로 없는 항·연결어는 버림 → "교정 금지" 지표는 구조상 0.
  - `moons_dump_assess`: 연결마다 성립 / 애매 / 근거 없음 + 이유. **별도 호출, 기본 숨김**(노드 패널 "내가 이은 것"의 눈 아이콘).
  - 비약은 그 노드의 MOONS 코멘트(더 살펴보기)로도 뜨고, ELK 지도에서는 주황 점선 `비약`.
  - 다의어: 노드에 보라색 `@`(뜻 목록 툴팁). 개념 컬렉션에서 `단어@뜻` 개념으로 이 노트의 언급이 옮겨짐(원래 개념의 하위로 연결).
- **개념 ID로 정렬한 대조** (6.3): 비교 결과에 둘 다 있음 / 원본에만 / 내 노트에만 개념 줄(개념 칩 → 개념 페이지).
- **다음 탐색 카드** (6.3, `v5/next-explore.ts`, `moons_next_explore`): 달라진 문장·빠진 문장·비약·설명 안 한 개념(왜소행성)마다 카드 하나 {질문, 개념, 근거 원문}. 모델이 빠뜨린 대상은 기본 질문 카드로 채워 비지 않음. 카드의 `질문으로 열기` → 질문 노트 생성(M5에서 질문 노트 화면).
- **앎의 상태** (1.1, 5.4): `Entry.knowledge` = 들어옴 → 정리됨(구조화) → 대조됨(비교) → 설명할 수 있음(남은 비율 ≥ 0.8 + 사용자가 "설명할 수 있어요" 누름). 노트 상단 칩. 기준은 `settings.explainableBar`(기본 0.8). 바뀌면 이벤트 로그에 남음(기존 저장 diff 기록).
- 운영자 모델 표에 단계 추가: 스파크 받아 적기, 다음 탐색.

## 6. 물을 것
- 스파크는 "A~E 같은 파이프라인"으로 다시 그리지 않고, 사용자의 묶음을 따르는 기존 지도 + 받아 적기 층으로 했음. 스파크도 자료처럼 명제 지도로 바꿔 그릴지(사용자 묶음은 섹션으로 유지 가능).
- "설명할 수 있음"의 사용자 확인을 버튼 한 번으로 했음. 직접 설명 스파크를 쓰게 할지.
